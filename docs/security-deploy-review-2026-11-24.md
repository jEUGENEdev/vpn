# Разбор замечаний к деплою и управлению VPN

База: `b2fae45`, 24 ноября 2026 года. Исправления проверялись на локальных
синтетических данных. Реальный VPS, ключи, firewall и установленные клиенты
не изменялись. Перечень ниже отделяет подтверждённые дефекты от предложений,
которые меняют модель доступа или требуют нативного испытания.

## Уточнения и сохранённые ограничения

- SHA-256 используется для случайных токенов, bcrypt — для пароля администратора.
  Generated secrets уже игнорировались Git; дополнительное blanket-исключение
  gitleaks не добавлено. Модели Device не экспортируют transport secrets.
- Серверные правила — механизм split tunneling, управляемый самим пользователем.
  Домен включает поддомены; это не изоляция недоверенных tenant-ов. Private egress
  контролируется независимо от пользовательских правил.
- `Decide` продолжает блокировать неканонические/невалидные цели. Автоматический
  direct для любого отказа Normalize ослабил бы fail-closed. Однословные имена,
  zone IPv6 и `_` не становятся допустимыми правилами; локальные устройства
  доступны напрямую по обычным IP, если приложение не отправлено только в VPN.
  Отдельное безопасное разрешение локальных имён/зон требует тестов всего DNS/TUN пути.
- Удаление пользователей Xray не разрывает уже принятые потоки, поэтому отзыв,
  блокировка и истечение сохраняют немедленный перезапуск. Округления TTL вверх
  нет: оно незаметно продлило бы доступ. Группировка правил, точечное закрытие
  sessions и Happy Eyeballs остаются отдельной оптимизацией.
- Формат bbolt пока один JSON на реальное изменение; кэш убирает повторное
  декодирование при чтении, а индекс — полный поиск device на bearer-запрос.
  Compact старых страниц/backup, отдельные buckets и отдельная операция удаления
  аккаунта не добавлены. `rejected` можно одобрить через существующий admin API;
  автоматическое освобождение заблокированных имён не выполняется.
- Admin sessions сохраняют максимум 8 часов. Idle TTL, управление firewall/
  sshd/fail2ban, ARM VPS, смена REALITY target и квоты полосы не внедрены этим
  изменением. Нативный Windows-лаунчер не получил fingerprint/key-auth.
- Метаданные источников остаются частью пользовательской очереди, а admin API
  уже выдаёт только allowlist полей без пользовательской routing policy.
  Полный аудит DNS/WFP/PF/Android и packet capture не заменяется этим PR.

## Проверки

Регрессионные сценарии воспроизводили исходные ошибки передачи секретов,
base64, public admin listener, bearer-only rotation, IPv6 rate limit, потери
выданного ключа, null maps, разрешений файлов и специальных IP-диапазонов.
Новые проверки также покрывают отказ commit, индексы после reopen, продление
с прежним SPKI, SAN migration и обновление TLS на существующем listener.

Результаты финального прогона и ограничения окружения фиксируются в PR.
Полный браузерный UI и нативные WFP/PF/Android проверки обязательны перед
выкатом; Linux compilation не является доказательством работы ACL/kill switch.
