# Приёмка перед использованием

Запускайте на отдельных тестовых устройствах/VM с доступом к локальной консоли. Нельзя считать выпуск готовым по одним unit-тестам или успешной упаковке.

Для каждого сценария проверяйте фактический трафик на физическом интерфейсе. При обращении к одобренному адресу там допустимы только соединения службы с VPN-сервером; соединений к реальному целевому IP быть не должно.

## Автоматизированные проверки CI

Windows Server 2025: MSI установился, служба запустила Wintun/WFP; Fake-DNS, direct IP, блокировка после локального одобрения без сервера и WFP после остановки службы пройдены. Android 15 x86_64 emulator: VpnService/TUN, Fake-DNS, direct IP и локальная защита при отсутствии сервера пройдены. macOS 15 Intel и macOS 26 Apple Silicon: PKG, служба/TUN, Fake-DNS, direct, локальная блокировка и сохранение PF после остановки службы пройдены. Это ограниченные smoke-тесты; строки таблицы выше относятся к полным сценариям на целевых устройствах, включая настоящий VPS и проверки пакетов.

## Предложения и приложения 0.2

1. Рабочий прямой TCP/UDP обмен не создаёт предложение; повторная ошибка одного источника создаёт его. Успех снимает только ошибку этого источника. Старые успешные discoveries 0.1 не отображаются.
2. Проверить несколько поддоменов и IP: одна раскрываемая группа на регистрируемый домен, отдельные private-suffix арендаторы и IP. Обновление не меняет порядок, фокус и раскрытие.
3. На Android, Windows и macOS определить владельца реального TUN-подключения. Доверить его, проверить блокировку без VPN, вернуть режим адресов. Автоматизированные нативные сценарии выполняют эти проверки на эмуляторе и установленных MSI/PKG.
4. При рабочем сервере доверенное приложение использует отдельный VPN-маршрут; другое приложение к тому же неразрешённому адресу остаётся прямым. Отзыв доверия сохраняет правила доменов; отзыв устройства прекращает оба VPN-маршрута.
5. При неизвестном владельце явно показать ограничение, не угадывать приложение и не переносить доверие на похожее имя/заменённый бинарник. Подтверждение и откладывание окна не вызывают поток повторных окон.

## История источников и поиск

- После сбоя прямого и защищённого запроса проверить точный адрес и источник в «Что происходит», подробностях и системном уведомлении. Сбой с неопределённым владельцем не должен приписываться известному приложению, которое также обращалось к этому адресу.
- После восстановления и исчезновения запроса из очереди источник старого события должен сохраниться. Общий сбой службы не должен изображаться запросом конкретного приложения.
- Найти старое событие, не входящее в последние три, по пути приложения и по IPv6; раскрыть/свернуть историю. Проверить пустую выдачу, очистку поля, сохранение фокуса, раскрытых подробностей и фильтра при обновлениях.
- Проверить поиск в каждом списке, включая источники внутри группы поддоменов, приложения с одинаковым именем и разными путями, устройства и аккаунты администратора. Действие из отфильтрованной строки должно затрагивать только выбранную запись. Поиск сам по себе не меняет доступ или маршрутизацию.
- `scripts/test-ui.cjs` содержит эти сценарии и снимки истории на desktop/mobile. Нативные уведомления и определение владельца в ОС требуют отдельной проверки на целевом устройстве.


## Ключи и переключатель VPN

На реальном VPS и каждой целевой платформе ещё требуется проверить:

1. Регистрация по имени, однократная выдача/копирование ключа, ожидание одобрения и вход только по ключу; отображение того же имени в админке и клиенте.
2. Выдача ключа старому аккаунту сохраняет его правила и ID. Старый пароль не принимается. Замена ключа закрывает реальные VPN-соединения всех устройств и отзывает старые коды.
3. Перевыпуск общего профиля: старый профиль не регистрирует и не подключает устройства, новый работает. Без массового отзыва текущие устройства продолжают работать; с отзывом теряют API и VLESS-доступ.
4. Отмена «Выключить VPN» ничего не меняет. Подтверждение переводит TCP/UDP напрямую, а выбор сохраняется после перезапуска. UI и Android-уведомление явно показывают выключенное состояние.
5. Включение закрывает уже открытые прямые соединения, в том числе запросы, начавшиеся во время переключения. При недоступном сервере защищённый адрес/доверенное приложение не выходит напрямую. Проверить пакетным захватом IPv4/IPv6, DNS-кэши и Android lockdown.

Go-тесты проверяют серверный отзыв, сохранение идентичности, изоляцию, перезапуск и маршрутизацию на локальных listener. `scripts/test-ui.cjs` содержит сценарии новых форм, однократной выдачи, подтверждения/отмены и переключателя; для запуска нужен доступный Chromium. Эти проверки не заменяют нативную проверку трафика.

## Проверки устройств и установки macOS

- При входе системное имя показано без редактирования; при его отсутствии доступны выбор своего устройства и добавление текущего, включая пустой список. Чужие аккаунты и платформы в выбор не попадают.
- Повторная авторизация сохранённого устройства не создаёт дубликат и инвалидирует оба прежних VPN-ключа и API-токен. Pair-код сохраняется на этапе выбора и расходуется атомарно при завершении.
- Удаление своего/другого устройства и старой отозванной записи удаляет запись и связанные коды. После перезапуска сервера она не появляется; обе старые VPN-учётные записи и API закрыты, активные TCP/UDP-потоки остановлены. Локальные разрешённые адреса остаются fail-closed после перезапуска клиента.
- JSON `/api/admin/accounts` не содержит правила, их счётчики или ревизию; интерфейс не отображает пользовательские разрешения.
- На Intel и Apple Silicon проверить **финальный** DMG: `hdiutil verify`, архитектуру, `codesign --verify --deep --strict` приложения, подпись агента из PKG, установку PKG из образа и запуск скопированного GUI. CI сохраняет `macos-signing.txt` и `macos-gui.txt`.
- На чистом Mac скачать DMG через браузер, сохранив quarantine. Для release обязательны `spctl` и stapled tickets приложения/PKG/DMG; preview не проходит обычное доверие Gatekeeper. Проверка на CI без quarantine не заменяет этот сценарий.
