# Обновление клиента поверх установленного

Проверка от **17 ноября 2026**. Основа: `main` на `20a5a9115bf1a9d770e31871ebfe52957b34c1d1`. Изменения ниже относятся к исходникам **0.2.1**. Опубликованный комплект в `installers/current/manifest.json` пока остаётся **0.2.0**, исходник `d067d97`.

## Результат проверки

| Windows | Постоянный UpgradeCode уже связывал установки; MSI всех выпусков имел 0.2.0 с разрешёнными обновлениями той же версии. Порядок удаления старого продукта не включал его в откат транзакции | MSI получает общую версию 0.2.1 и стабильный ProductCode на выпуск. Новая версия заменяет предыдущую; повторный `/i` того же MSI включает repair. Более старый MSI блокируется. Удаление предыдущего продукта перенесено после InstallInitialize для отката при ошибке |
| macOS | Пользователь отдельно копировал UI и ставил службу; замена только UI оставляла старый агент. Bootout выполнялся в postinstall, уже после замены файлов | Один `Install-LineVPN.pkg` устанавливает и UI, и службу. Preinstall ждёт завершения UI, LaunchDaemon и worker до замены. Для Windows механизм major upgrade внутренне удаляет файлы предыдущего продукта, затем устанавливает новые в одной транзакции. Предварительно удалять приложение вручную не нужно. Данные клиента не являются компонентами MSI.

## Что сохраняется

Каталоги данных не входят в устанавливаемый payload: `%ProgramData%\LineVPN` на Windows, `/var/lib/linevpn` на macOS, приватный `filesDir` приложения `dev.linevpn.app` на Android. Установщики не очищают профиль, ключи сессии, идентификатор устройства, подтверждённые и ожидающие правила, решения приложений или состояние кнопки VPN. Настройки Electron также остаются в прежнем userData при неизменных appId и имени приложения.

Это проверка **установки поверх**. Удаление Android-приложения или очистка его данных удаляет локальное состояние. Восстановление правил из аккаунта после удаления данных — отдельное изменение [PR #20](https://github.com/jEUGENEdev/vpn/pull/20). Оба изменения включены в совместное объединение; сначала требуется обновить сервер, затем клиенты и дождаться синхронизации до удаления данных.

## Как обновлять

1. Скачать комплект для своей платформы и архитектуры, сверить его manifest и SHA-256.
2. Запустить новый MSI / `Install-LineVPN.pkg` из DMG / APK поверх установленного приложения. Предварительная деинсталляция и очистка данных не требуются.
3. Открыть клиент и проверить прежний вход, то же устройство, адресные правила, решения для приложений и сохранённое состояние включения VPN.

Повторный запуск **того же** установщика восстанавливает/переустанавливает текущую версию с сохранением данных; более новой программы в таком файле нет. Windows код 3010 означает, что для завершения требуется перезагрузка. macOS после сбоя установки может потребовать повторного запуска PKG: транзакционный откат всего macOS-пакета здесь не заявлен.

Для старых опубликованных DMG 0.2.0 нужны оба действия: заменить `/Applications/LineVPN.app` и установить `Install-LineVPN-Service.pkg` из **того же** образа. Новый единый PKG появится только после новой сборки и публикации.

## Версии и подпись сборок

Версия задаётся в `apps/desktop/package.json`; `package-lock.json` должен совпадать. Python-упаковщики и Gradle читают её, а `scripts/package_version.py --check-newer` отклоняет повторную публикацию с версией не выше предыдущего manifest. Формат — три числа, major/minor до 255, patch до 999. Android-код: `major * 1000000 + minor * 1000 + patch`; эта схема сохраняет порядок версий и превышает старый versionCode 2.

Для Android нужны **существующий** keystore и переменные `ANDROID_KEYSTORE` (абсолютный путь), `ANDROID_STORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`. В GitHub Actions используются одноимённые секреты паролей/alias и `ANDROID_KEYSTORE_BASE64` для файла. Workflow восстанавливает временный файл с правами 0600 и удаляет его в конце. Наличие/содержимое секретов в аккаунте этой проверкой не подтверждалось и не изменялось. При их отсутствии сборка остановится до выпуска несовместимого APK.

PR и сборки вне main используют `LINEVPN_ANDROID_TEST_ONLY=1` только с debug-вариантом: им не требуются секреты выпуска. Такие APK не обновляют `installers/current`. Публикация повторно проверяет настоящий APK независимо от флага сборки.

Ожидаемый SHA-256 сертификата берётся из предыдущего manifest: `b13dfe366940dc70d27e244c8bf17ed18ff3dfdad93713bdbc1b91cbfa85f0b1`. Это публичный отпечаток, не приватный ключ. Он переносится в новый manifest. Другой сертификат требует отдельной продуманной миграции; удалять установленное приложение ради обхода ошибки обновления не следует.

`npm run dist` теперь направляет сборку в штатный платформенный скрипт, чтобы обычный electron-builder не создавал отдельный пакет UI без управляемой службы. macOS сначала собирает и подписывает app, затем помещает его и агент в PKG, и только затем создаёт DMG; PKG не вложен внутрь самого app. Путь приложения фиксирован в `/Applications`, relocation отключён.

## Проверки отдельного PR до объединения

Актуальные проверки объединённого кода перечислены в [отчёте интеграции](pr-20-24-integration.md).

- 10 тестов `python3 scripts/test-installer-upgrade.py`: fresh/upgrade/repeat, отказ от downgrade до остановки процессов, незавершившийся GUI/worker/service, ошибочный bootout при уже остановленном сервисе, запрет другого тома, повторное использование service account, сохранение файлов, MSI identity/repair/rollback и отбраковка неправильной Android-подписи/идентификатора/версии. Команды macOS подменяются только во временной копии сценария; это не запуск Apple Installer.
- `python3 scripts/test-network-packaging.py`: генерация WiX XML и проверка порядка service/recovery actions; синтаксис macOS-скриптов.
- `go test -race -tags with_gvisor ./internal/client` и `go vet -tags with_gvisor ./internal/client`: пройдены. Новая регрессия дважды открывает прежний профиль и решения приложений, проверяет сохранение account/device ID, токенов, правил, очереди разрешений и режимов on/off. Существующий тест DNS проверяет сохранение его базы после перезапуска.
- Gradle `--offline --no-daemon :app:assembleDebug`: пройдено с JDK 21 и ранее собранным `core.aar` из комплекта d067d97. Исходники Go не изменены, bridge и LineVpnService совпадают с этой сборкой. Первые попытки использовали неполный JRE и устаревший AAR; после выбора полного JDK и актуального AAR сборка прошла. Это проверка Gradle/Kotlin/упаковки, а не новая сборка Go-ядра.
- Реальный полученный APK проверен `apksigner`/`aapt` через `verify_android_update.py`: подпись совпадает с опубликованным сертификатом, package ID `dev.linevpn.app`, versionName 0.2.1, versionCode 2001.
- Bash/JS/Python syntax, YAML и `git diff --check`: пройдены.

В нативные CI-сценарии добавлены повторный `/i` MSI, повторный запуск полного PKG и `adb install -r` с проверкой сохранённых данных. **Эти нативные сценарии в текущем Linux-окружении не запускались.** Новый APK был создан только для проверки, комплект установщиков не опубликован.

## Перед выпуском

На изолированных Windows/macOS/Android нужны проверки **реального прежнего опубликованного пакета → нового**, повторной установки нового пакета, сохранения одного экземпляра приложения/службы, профиля/правил/устройства и режима off. Для Windows дополнительно проверить rollback при ошибке после удаления прежней версии, отсутствие старых файлов и завершение обновления после 3010; для macOS — обе архитектуры, запущенный UI/worker, отказ остановки, Gatekeeper и восстановление после обрыва установки; для Android — установка из файлового менеджера поверх опубликованного APK и отклонение другого сертификата/старой версии без очистки данных.

При объединении с [PR #21](https://github.com/jEUGENEdev/vpn/pull/21) recovery исключён из пути обновления, firewall сохраняется при остановке worker. Перед выпуском требуется проверить сеть при обновлении на реальных ОС. Уже установленный старый MSI исполняет свой собственный uninstall action; изменение нового MSI не переписывает его задним числом.

Основания: [Microsoft: Major Upgrades](https://learn.microsoft.com/en-us/windows/win32/msi/major-upgrades), [ProductVersion](https://learn.microsoft.com/en-us/windows/win32/msi/productversion), [WiX: MajorUpgrade](https://docs.firegiant.com/wix/schema/wxs/majorupgrade/), [SetProperty](https://docs.firegiant.com/wix/schema/wxs/setproperty/), [Android: How app updates work](https://developer.android.com/google/play/app-updates).
