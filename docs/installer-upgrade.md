# Установка и удаление «Сеть» 0.4

В исходниках 0.4 убраны repair и установка поверх desktop-клиента. Сначала
выполните полное удаление, затем установите приложение с нуля. Старые файлы
в `installers/current` не меняются до успешной сборки и публикации нового комплекта.

Перед удалением сохраните профиль сервера и ключ доступа. Удаление очищает
локальный вход, идентичность устройства, правила, очередь несохранённых решений,
DNS-базу и состояние интерфейса. Аккаунт и подтверждённые правила на сервере
не удаляются; после нового входа создаётся новое устройство. Старое устройство
можно отозвать в аккаунте. Без профиля и ключа заново войти нельзя.

| Платформа | Удаление | Новая установка |
| --- | --- | --- |
| macOS Intel / Apple Silicon | Новый universal DMG → «Установщик Сеть» → «Удалить» | Повторно открыть тот же установщик → «Установить» |
| Windows x64 | Параметры → Приложения → «Сеть» → Удалить; при необходимости перезагрузить | Запустить новый MSI, дождаться завершения; открыть «Сеть» из меню «Пуск» |
| Android 10+ | Системное удаление приложения | Установить APK, заново разрешить VPN и уведомления |

На macOS новый DMG использует собственные сценарии и агент удаления, даже если
старый установленный агент отсутствует. На Windows новый MSI хранит независимую
копию средства удаления в своей Binary table: отсутствие EXE на диске не ломает
удаление этого пакета. Эта возможность не изменяет уже выпущенные старые MSI.
После удаления старого MSI новая установка очищает оставленные им данные.

Удаление сначала останавливает процессы, затем освобождает принадлежащие клиенту
PF/WFP и DNS-настройки и только после успеха удаляет файлы. Чужие приложения,
правила firewall и DNS не сбрасываются. На macOS удаляется также выделенная
системная учётная запись `_linevpn`, если её параметры соответствуют установщику.
Отдельных пользовательских сценариев «восстановления» больше нет.

Повторный MSI `/i`, `/fa` и установка другой версии поверх зарегистрированного
продукта отклоняются до изменения файлов. Кнопка Repair скрыта через ARPNOREPAIR;
запрет командной строки проверяется отдельно. На macOS остатки приложения,
данных, receipt или службы также требуют сначала удаления. Прерванная установка
обрабатывается тем же порядком «Удалить → Установить».

Успешная установка требует ответа локального HTTPS API с проверкой сертификата
и токена. При включённом VPN также обязательны TUN и сетевой фильтр, без ошибки
инициализации. Это проверяет локальный клиент; доступ к конкретному серверу VPN
проверяется после добавления профиля и входа.

Сбой работающей службы не отключает защиту автоматически. Только явное выключение
VPN или удаление освобождает сеть. При откате неудачной **чистой** Windows-установки
встроенное средство удаляет созданные ей фильтры и данные после остановки службы.

Проверки: `test-installer-upgrade.py` проверяет переносимые сценарии и MSI XML;
`test-desktop-clean-install.py` исполняет отказ повторной установки, удаление,
новую установку, новую сессию и удаление при отсутствующем агенте на Windows/macOS.
`test-android.sh` проверяет повторную установку APK и отдельный цикл полного
удаления/установки. Наличие сценариев не означает, что конкретный пакет уже прошёл
их: результаты должны быть подтверждены CI для его commit.
