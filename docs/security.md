# Границы защиты

## Приоритет — доступность сети

Клиенты используют автоматический прямой резерв. Это сознательно допускает выход трафика без VPN при сбое. Настройка не является kill switch и не обещает отсутствие утечек. Статус и уведомление показывают потерю VPN-защиты.

| Состояние | Маршрут |
|---|---|
| VPN выключен | Обычная сеть ОС, без TUN |
| Адрес не одобрен | Прямое соединение |
| Одобренный адрес / доверенное приложение, VPN доступен | VLESS → XHTTP → REALITY |
| VPN/API недоступен, вход истёк или транспорт не настроен | Прямое соединение без VPN-защиты |
| Неизвестный синтетический IP | Ошибка: исходный адрес неизвестен |

Сбой открытия VPN-соединения допускает прямую попытку, если запрос не отменён. Ошибка чтения/записи или отсутствие первого TCP-ответа после отправки данных в течение 20 секунд включает прямой резерв на 30 секунд **только для этой пары адрес/приложение, протокола и порта**. Другие разрешённые соединения продолжают использовать VPN. Зависший TCP-поток закрывается; уже отправленные данные не переигрываются автоматически, повтор выполняет приложение. После паузы новые подключения снова пробуют VPN. Работа API и ответ другого адреса не доказывают восстановление сбоившего направления: уведомление о его восстановлении требует полученных через VPN данных именно этого направления.

UDP может быть односторонним, поэтому отсутствие ответа и обычное истечение времени ожидания UDP-сессии сами по себе не включают прямой резерв. Ошибки открытия/записи и разрыв транспортного канала по-прежнему допускают резерв для конкретного направления. Каждая UDP-пара адрес/порт назначения получает отдельную NAT-сессию и проверку разрешений, даже когда приложение использует один исходный сокет для нескольких медиасерверов.

Сохранённые правила и выбор пользователя не стираются при сбое. При смене маршрута старые соединения закрываются. Серверная авторизация, отзыв ключей и запреты серверного egress сохраняются: прямой резерв не даёт отозванному устройству доступ к VPN-серверу.

Подключение дополнительного устройства, включение отдельного ключа доверенных приложений и добавление адресных разрешений применяются без остановки действующих серверных потоков. Неизменная конфигурация не перезапускает Xray. Удаление устройств, замена ключей, блокировка аккаунта и сужение разрешений по-прежнему отменяют серверный экземпляр и его активные потоки: это обеспечивает немедленный отзыв, но может потребовать переподключения остальных устройств.

Публичные суффиксы, wildcard, URL, порт и CIDR не принимаются как разрешение. Доменные правила сравниваются по границе DNS-меток; используется IDNA. Серверный Xray по умолчанию направляет неразрешённый трафик в blackhole и проверяет реальные IP, запрещая внутренние сети, localhost, metadata, link-local и переходные IPv6-префиксы.

## DNS и остановка

TUN перехватывает обычный DNS TCP/UDP 53, выдаёт стабильные Fake-IP для A/AAAA с TTL 0 и хранит соответствия на диске. Неизвестные Fake-IP не передаются в обычную сеть. Сторонние приложения могут игнорировать TTL; после обновления старого клиента может понадобиться перезапуск браузера. DoT больше не блокируется специально. DoH/DoT и встроенные IP могут скрывать домен и идти напрямую. MX/TXT/SRV и другие типы DNS пока не пересылаются; это ограничение preview.

Новые Windows/macOS-клиенты не устанавливают постоянные WFP/PF-запреты и не используют StrictRoute. macOS не переписывает DNS физических интерфейсов: временная DNS-запись SystemConfiguration существует, пока открыт принадлежащий агенту stdin процесса scutil. Закрытие агента завершает сессию и удаляет её запись. Старые фильтры и DNS удаляются при миграции, выключении и деинсталляции; затрагиваются только настройки Линии. Неисправный DNS-бэкап не останавливает очистку других интерфейсов: оставшийся адрес Линии удаляется, при отсутствии иных DNS используется DHCP. Сохранённые пользовательские DNS не перезаписываются.

На macOS привилегированный supervisor выполняет recovery после завершения сетевого worker, который работает под отдельным UID. Windows MSI выполняет проверяемую очистку после StopServices до удаления файлов. При ошибке recovery удаление прерывается, сохраняя инструмент восстановления.

Android закрывает VPN-дескриптор; маршруты и DNS принадлежат VpnService. **«Блокировать соединения без VPN» необходимо отключить** для доступности сети после остановки/сбоя. Приложение не имеет права менять эту настройку ОС или политику администратора; сообщает о ней и открывает настройки. Отказ создания TUN оставляет локальный UI для повторной попытки.

Нативная проверка остановки, crash, обновления, удаления, IPv4/IPv6, сна и смены интерфейса обязательна по [acceptance.md](acceptance.md). Кросс-сборка и unit-тесты не заменяют её. Восстановление сети не гарантирует доступность конкретного сайта или самого провайдера.

## Сервер и инфраструктура

REALITY защищает клиентский канал, собственный HTTPS-домен не требуется. API использует TLS 1.3 с закреплением SPKI публичного ключа. В коде включён `InsecureSkipVerify` только вместе с обязательным `VerifyConnection`, проверяющим ключ и срок сертификата; пустой/чужой pin отклоняется. Перенаправления HTTP запрещены.

Вход пользователей выполняется по случайным 256-битным ключам `lnv_…`; сервер хранит только их SHA-256, как и хэши токенов устройств и одноразовых кодов привязки (256 и 120 бит). Логин — несекретное имя аккаунта. Старые bcrypt-хэши не принимаются для входа и удаляются из записи при выпуске ключа. Замена ключа отзывает все устройства и коды аккаунта; сохранённые правила остаются. Админ-пароль задаётся через Ansible Vault, на сервере читается из файла 0600; сессия администратора живёт восемь часов и хранится в памяти. Admin/API не используют cookies, все изменения требуют bearer-токен. Пароли и ключи не пишутся в access log; журналы посещений Xray отключены. База хранит разрешения и очередь запросов, поэтому резервные копии конфиденциальны.

Общий профиль `linevpn://…?pin=…&access=…` содержит случайный ключ подключения. Он требуется для регистрации, входа нового устройства и использования кода привязки через заголовок `X-LineVPN-Profile`; одного профиля недостаточно для доступа к аккаунту/VLESS. Ключ профиля хранится в серверной БД с правами 0600, чтобы администратор мог повторно экспортировать текущий профиль. Перевыпуск атомарно меняет его и отзывает коды привязки. Уже подключённые устройства сохраняют доступ, если администратор явно не выбрал их отзыв. TLS/REALITY private keys эта ссылка не содержит. Утечка приватных ключей сервера или диска VPS требует отдельного восстановления доверия; замена ссылки её не устраняет.

VPS-провайдер всё равно может видеть IP-адреса, объём и время соединений; оператор гипервизора потенциально видит память/диск VM. Исходящий HTTP к сайту не шифруется магически после выхода из VPN. Ни REALITY, ни этот проект не обещают невидимость для владельца VPS или защиту от компрометации серверной ОС.

Локальный desktop UI доступен пользователям устройства через токен loopback-службы. В preview это общий аккаунт VPN для данной машины: локальных пользователей ОС нельзя считать изолированными друг от друга администраторами политики. Серверные токены/ключи хранятся отдельно с ограниченными правами.
