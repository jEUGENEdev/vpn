# Границы защиты

## Маршрутизация

Таблица описывает включённый VPN. Явное «Выключить VPN» с подтверждением переводит трафик напрямую до следующего включения; состояние сохраняется. Это действие пользователя, а не автоматическая реакция на сбой. Неизвестные Fake-IP по-прежнему отвергаются.

| Состояние адреса | Канал | При ошибке VPN |
|---|---|---|
| Не одобрен | Прямое соединение из службы | Остаётся прямым |
| Одобрен | VLESS → XHTTP → REALITY | Блокируется, прямого fallback нет |
| Неизвестный адрес из Fake-IP диапазона | Запрет | Запрет |

Публичные суффиксы (`com`, `co.uk`, `github.io`), wildcard, URL, порт и CIDR не принимаются как разрешение. Сравнение выполняется по границе DNS-меток. `example.com` не разрешает `evil-example.com`. Unicode нормализуется через IDNA, IPv4-mapped IPv6 приводится к IPv4.

Xray на сервере по умолчанию направляет всё в blackhole. Разрешающие правила привязаны к VLESS-пользователю конкретного устройства. Сервер дополнительно проверяет реальные IP перед исходящим соединением и запрещает внутренние сети, localhost, link-local, metadata, multicast и переходные IPv6-префиксы. Поэтому разрешение домена не даёт доступ к внутренней инфраструктуре VPS через DNS rebinding.

Нажатие «Одобрить» сначала сохраняет локальную защиту и закрывает соответствующие прямые соединения, затем отправляет запрос серверу. Даже если API не ответил, адрес не возвращается к direct: локальная защита остаётся до успешного одобрения или явного удаления. Смена политики закрывает старые соединения. При неудачной синхронизации последняя сохранённая политика не превращается в пустой список; одобренные адреса остаются заблокированными. Серверные изменения применяются через остановку старого Xray перед запуском нового: сбой конфигурации оставляет data plane закрытым.

## DNS и наблюдаемость

При включённом VPN клиент перехватывает обычный DNS (TCP/UDP 53), возвращает стабильные Fake-IP для A/AAAA и хранит соответствия на диске. Даже после перезапуска старый Fake-IP не получает другой домен. Удаление DNS-базы при сохранённых кэшах не приводит к прямому соединению: неизвестные Fake-IP блокируются. HTTPS/SVCB DNS-ответы не передают ECH/IP-подсказки, DoT на 853 блокируется. Другие типы DNS-запросов (например, MX/TXT/SRV) в preview не пересылаются; приложения, которым они нужны, требуют отдельной проверки совместимости.

**Существенное ограничение:** произвольный DoH внутри HTTPS, собственный DNS приложения, встроенные IP и DNS-кэши до запуска клиента могут скрывать доменное имя. Неизвестный реальный IP по требованиям пользователя идёт напрямую. Нельзя одновременно гарантировать определение скрытого домена в любом зашифрованном потоке и автоматически разрешать все неодобренные IP напрямую. Для доменных гарантий приложения должны использовать DNS клиента; отключите Secure DNS/DoH в приложениях. Одобренный IP защищается независимо от DNS. Обходы должны быть проверены на целевых приложениях до production; этот проект не выдаёт отсутствие утечек для произвольного внешнего DNS за доказанный факт.

Автоматическая синхронизация политики между устройствами происходит каждые 5 секунд при включённом VPN и доступном API. В выключенном режиме запросы выполняются только для явных действий пользователя в аккаунте. Новое одобрение с другого устройства защищает домен после получения новой версии. Офлайн-устройство не может узнать о новом правиле до восстановления связи. Строго одновременная активация на всех устройствах потребует отдельного протокола lease/ack и не заявляется в preview.

## Защита при падении

Android полагается на явно включённый системный lockdown. Windows использует persistent WFP, macOS — PF anchor и отдельный UID. При падении фоновой службы с включённым VPN может блокироваться вся сеть. Явное выключение через клиент восстанавливает обычную сеть и сохраняется после перезапуска; на Android перед этим нужно снять системный lockdown. Проверка конкретного сетевого стека, загрузки ОС, DHCP, IPv6, смены интерфейса, существующих соединений и совместимости с другими firewall обязательна по `acceptance.md`. Наличие правил в коде не является доказательством, что ни одна платформа не пропускает пакеты.

## Сервер и инфраструктура

REALITY защищает клиентский канал, собственный HTTPS-домен не требуется. API использует TLS 1.3 с закреплением SPKI публичного ключа. В коде включён `InsecureSkipVerify` только вместе с обязательным `VerifyConnection`, проверяющим ключ и срок сертификата; пустой/чужой pin отклоняется. Перенаправления HTTP запрещены.

Вход пользователей выполняется по случайным 256-битным ключам `lnv_…`; сервер хранит только их SHA-256, как и хэши токенов устройств и одноразовых кодов привязки (256 и 120 бит). Логин — несекретное имя аккаунта. Старые bcrypt-хэши не принимаются для входа и удаляются из записи при выпуске ключа. Замена ключа отзывает все устройства и коды аккаунта; сохранённые правила остаются. Админ-пароль задаётся через Ansible Vault, на сервере читается из файла 0600; сессия администратора живёт восемь часов и хранится в памяти. Admin/API не используют cookies, все изменения требуют bearer-токен. Пароли и ключи не пишутся в access log; журналы посещений Xray отключены. База хранит разрешения и очередь запросов, поэтому резервные копии конфиденциальны.

Общий профиль `linevpn://…?pin=…&access=…` содержит случайный ключ подключения. Он требуется для регистрации, входа нового устройства и использования кода привязки через заголовок `X-LineVPN-Profile`; одного профиля недостаточно для доступа к аккаунту/VLESS. Ключ профиля хранится в серверной БД с правами 0600, чтобы администратор мог повторно экспортировать текущий профиль. Перевыпуск атомарно меняет его и отзывает коды привязки. Уже подключённые устройства сохраняют доступ, если администратор явно не выбрал их отзыв. TLS/REALITY private keys эта ссылка не содержит. Утечка приватных ключей сервера или диска VPS требует отдельного восстановления доверия; замена ссылки её не устраняет.

VPS-провайдер всё равно может видеть IP-адреса, объём и время соединений; оператор гипервизора потенциально видит память/диск VM. Исходящий HTTP к сайту не шифруется магически после выхода из VPN. Ни REALITY, ни этот проект не обещают невидимость для владельца VPS или защиту от компрометации серверной ОС.

Локальный desktop UI доступен пользователям устройства через токен loopback-службы. В preview это общий аккаунт VPN для данной машины: локальных пользователей ОС нельзя считать изолированными друг от друга администраторами политики. Серверные токены/ключи хранятся отдельно с ограниченными правами.
