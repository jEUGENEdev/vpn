# Границы защиты

## VPN до явного выключения

Пока VPN включён, разрешённые адреса (включая локальные ожидающие разрешения) и доверенные приложения используют только VPN. Недоступность API, истечение/отзыв доступа, отсутствие app-credential, ошибка подключения/чтения/записи и таймаут не разрешают прямую попытку. Правила сохраняются после перезапуска. Кэш ошибок служит только диагностике; его истечение не меняет маршруты.

| Состояние | Маршрут |
|---|---|
| Пользователь подтвердил «Выключить VPN» | Все адреса и приложения напрямую |
| VPN включён, адрес не одобрен и приложение не доверенное | Напрямую |
| Разрешённый адрес / доверенное приложение, VPN доступен | VLESS → XHTTP → REALITY |
| Защищённый адрес / приложение, VPN/API недоступен или доступ отозван | Блокировка; повтор только через VPN |
| Неизвестный синтетический IP | Ошибка: исходный адрес неизвестен |

Зависший TCP-поток закрывается после 20 секунд без первого ответа; приложение может повторить его через VPN. Односторонний UDP сам по себе не считается сбоем. Данные не воспроизводятся по другому маршруту. При изменении режима или правил закрываются затронутые соединения, включая прямые потоки, которые только что стали защищёнными. Состояния `protection_blocked` и `partial_outage` сообщают о недоступности без разрешения прямого маршрута.

## Нативная сеть

Windows использует постоянные правила WFP для IPv4/IPv6, macOS — отдельный PF-anchor `linevpn`. За пределами TUN разрешены сокеты агента и служебный трафик, необходимый для сети. Агент проверяет пользовательскую политику для каждого подключения. При потере TUN/worker может блокироваться вся сеть: определить владельцев и правила без рабочего перехвата нельзя. Аварийный выход и обновление не вызывают recovery. Снять защиту можно кнопкой выключения или отдельным явным административным recovery/удалением клиента.

macOS сохраняет сброс привилегий до `_linevpn`; правила TUN привязаны к интерфейсу, чтобы их состояния не разрешали выход через физический интерфейс. DNS физических интерфейсов не переписываются: временная запись SystemConfiguration удаляется при завершении сессии scutil. PF — механизм текущего preview, не публичный API Apple; для распространения и строгих системных гарантий нужен переход к Network Extension ([Apple TN3165](https://developer.apple.com/documentation/technotes/tn3165-packet-filter-is-not-api)). Правила других PF/WFP-провайдеров при recovery не удаляются; включение PF сбрасывает существующие состояния соединений для исключения обхода новой политики.

Android удерживает дополнительный TUN-дескриптор, чтобы отказ запуска Go-стека не возвращал сеть напрямую. При ручном выключении без lockdown интерфейс закрывается. При включённом lockdown интерфейс остаётся, но все соединения идут через прямые `protect()`-сокеты без VPN-сервера; системный значок VPN может оставаться. Системную блокировку приложение не снимает.

**Для защиты Android при завершении всего процесса необходимы «Постоянная VPN» и «Блокировать соединения без VPN».** Обычное приложение не может включить эти настройки самостоятельно. Отзыв разрешения/снятие блокировки пользователем меняет системные гарантии ([Android VPN](https://developer.android.com/develop/connectivity/vpn)).

Нативные сценарии crash, сон/пробуждение, смена интерфейса, обновление и трафик IPv4/IPv6 требуют проверки на целевых ОС. Unit-тесты и кросс-сборка не подтверждают отсутствие пакетов на физическом интерфейсе. До старта системной защиты при загрузке ОС и при её административном отключении гарантий нет.

## DNS и атрибуция

TUN перехватывает обычный DNS TCP/UDP 53, выдаёт Fake-IP для A/AAAA с TTL 0 и сохраняет соответствия. Неизвестные Fake-IP никогда не отправляются напрямую. DoH/DoT и встроенные IP могут скрывать домен: доменное правило не покрывает нераспознанный IP автоматически. Доверие приложению работает при успешной идентификации владельца ОС; неподдерживаемая или неудачная атрибуция не может безопасно приписать поток другому приложению. Для таких сервисов нужны явные правила IP либо подходящая системная идентификация. MX/TXT/SRV пока не пересылаются.

Публичные суффиксы, wildcard, URL, порт и CIDR не принимаются как разрешения. Домены сравниваются по границе DNS-меток с IDNA. Серверный Xray по умолчанию блокирует неразрешённый трафик, внутренние сети, localhost, metadata, link-local и переходные IPv6-префиксы.

## Сервер и инфраструктура

REALITY защищает клиентский канал, собственный HTTPS-домен не требуется. API использует TLS 1.3 с закреплением SPKI публичного ключа. В коде включён `InsecureSkipVerify` только вместе с обязательным `VerifyConnection`, проверяющим ключ и срок сертификата; пустой/чужой pin отклоняется. Перенаправления HTTP запрещены.

Вход пользователей выполняется по случайным 256-битным ключам `lnv_…`; сервер хранит только их SHA-256, как и хэши токенов устройств и одноразовых кодов привязки (256 и 120 бит). Логин — несекретное имя аккаунта. Старые bcrypt-хэши не принимаются для входа и удаляются из записи при выпуске ключа. Замена ключа отзывает все устройства и коды аккаунта; сохранённые правила остаются. Админ-пароль задаётся через Ansible Vault, на сервере читается из файла 0600; сессия администратора живёт восемь часов и хранится в памяти. Admin/API не используют cookies, все изменения требуют bearer-токен. Пароли и ключи не пишутся в access log; журналы посещений Xray отключены. База хранит разрешения и очередь запросов, поэтому резервные копии конфиденциальны.

Общий профиль `linevpn://…?pin=…&access=…` содержит случайный ключ подключения. Он требуется для регистрации, входа нового устройства и использования кода привязки через заголовок `X-LineVPN-Profile`; одного профиля недостаточно для доступа к аккаунту/VLESS. Ключ профиля хранится в серверной БД с правами 0600, чтобы администратор мог повторно экспортировать текущий профиль. Перевыпуск атомарно меняет его и отзывает коды привязки. Уже подключённые устройства сохраняют доступ, если администратор явно не выбрал их отзыв. TLS/REALITY private keys эта ссылка не содержит. Утечка приватных ключей сервера или диска VPS требует отдельного восстановления доверия; замена ссылки её не устраняет.

VPS-провайдер всё равно может видеть IP-адреса, объём и время соединений; оператор гипервизора потенциально видит память/диск VM. Исходящий HTTP к сайту не шифруется магически после выхода из VPN. Ни REALITY, ни этот проект не обещают невидимость для владельца VPS или защиту от компрометации серверной ОС.

Локальный desktop UI доступен пользователям устройства через токен loopback-службы. В preview это общий аккаунт VPN для данной машины: локальных пользователей ОС нельзя считать изолированными друг от друга администраторами политики. Серверные токены/ключи хранятся отдельно с ограниченными правами.
