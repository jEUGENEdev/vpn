# Границы защиты

## Ошибки соединений при работающем клиенте

Сохранённое решение направлять адрес или приложение через VPN не меняется при ошибке. Прямой резерв для такого трафика запрещён. Полный прямой режим включает пользователь кнопкой «Выключить VPN».

| Состояние | Маршрут |
|---|---|
| VPN выключен | Напрямую; Android lockdown может сохранять локальный TUN |
| Адрес не одобрен, приложение не доверенное | Прямое соединение |
| Одобренный адрес, приложение явно выбрало «по адресам» или доверие | VLESS → XHTTP → REALITY |
| Одобренный адрес, приложение неизвестно / ожидает решения / VPN запрещён | Блокировка; общее правило не даёт доступ к туннелю |
| Доверенное приложение, адрес вне списка | Отдельный credential приложения → VPN |
| Режим «Весь трафик», любое приложение / неизвестный источник | VPN для всех перехваченных TCP/UDP; при недоступности блокировка |
| Ошибка отдельного VPN-соединения | Повторная попытка только через VPN |
| Транспорт не настроен или доступ отозван | Защищаемые адреса/приложения блокируются |
| Временная ошибка API синхронизации | Сохранённые правила и действующие соединения сохраняются |
| Неизвестный синтетический IP | Ошибка: исходный адрес неизвестен |

Отсутствие первого ответа не доказывает сбой TCP/UDP: загрузка может быть односторонней, а ответ сервера — медленным. Клиент больше не закрывает VPN-поток через 20 секунд молчания. Локальные дедлайны, отмена и закрытие не считаются поломкой VPN; EOF неиспользованного или уже ответившего TCP-потока также не означает сбой. EOF после отправки данных без ответа остаётся ошибкой: Xray может так сообщить об асинхронном отказе подключения. Ошибка одного потока учитывается один раз, автоматически переигрывать его данные на другом маршруте нельзя.

`partial_outage` и `vpn_issues` показывают ошибки конкретных адресов, приложений, протоколов и портов. Ошибка остаётся без подтверждённого восстановления до получения данных от того же назначения. Ответ другого адреса и истечение прежних 30 секунд не создают ложное сообщение о восстановлении. Список ограничен 1000 записями и не содержит секретов или полезной нагрузки. Уведомления ограничены по частоте.

Ошибка `/api/sync` (таймаут, 5xx, некорректный ответ) выставляет `sync_pending`, но не закрывает рабочие потоки. Ответы 401/403 по-прежнему отзывают локальные ключи и закрывают защищённые соединения. Сервер продолжает самостоятельно проверять доступ. При смене политики затронутые соединения закрываются.

Эти гарантии относятся к обработке соединений работающим TUN. Они не доказывают защиту при падении процесса, отсутствии TUN или перезапуске сетевой службы: существующие ограничения платформ описаны ниже и требуют отдельной нативной проверки.

## Нативная сеть

**Android, выборочный режим:** системная VPN-сеть охватывает только приложения с
решением «по адресам» или «доверять» и само приложение «Сеть». Приложения без
разрешения (`pending`, `denied`, ещё не установленные/неизвестные) используют
обычную сеть и её DNS. Для них не действуют ни разрешения, ни блокировки адресов
внутри TUN; таблица выше описывает перехваченный трафик. Это осознанная граница
выборочной защиты: разрешение адреса не включает в VPN остальные приложения.
Режим «Весь трафик» по-прежнему охватывает все приложения. Смена разрешения
или режима перестраивает системный охват без ручного выключения VPN.

Расширение охвата выполняется до сохранения нового разрешения, с сохранением
ранее защищаемых приложений; сужение — после сохранения. Ошибка установления
нового интерфейса не закрывает старый удерживаемый дескриптор. После успешного
установления Android удерживает новый дескриптор, даже при ошибке дублирования
или запуска Go-стека. Старые потоки закрываются, поздние результаты подключений
отбрасываются по `routeEpoch`.

Системное исключение не гарантирует сокрытие самого факта VPN: стороннее
приложение может проверять интерфейсы устройства независимо от своего маршрута.
При включённой настройке Android **«Блокировать соединения без VPN»** исключённые
приложения теряют интернет. Клиент показывает это ограничение и не отключает
системную защиту самостоятельно. Без lockdown защита при смерти всего процесса
не гарантируется. [Модель per-app VPN Android](https://developer.android.com/develop/connectivity/vpn).

Windows использует постоянные правила WFP для IPv4/IPv6, macOS — отдельный PF-anchor `linevpn`. За пределами TUN разрешены сокеты агента и служебный трафик, необходимый для сети. Агент проверяет пользовательскую политику для каждого подключения. При потере TUN/worker может блокироваться вся сеть: определить владельцев и правила без рабочего перехвата нельзя. Аварийный выход не вызывает очистку сети; установка поверх запрещена. Снять защиту можно кнопкой выключения или явным удалением клиента.

macOS сохраняет сброс привилегий до `_linevpn`; правила TUN привязаны к интерфейсу, чтобы их состояния не разрешали выход через физический интерфейс. DNS физических интерфейсов не переписываются: временная запись SystemConfiguration удаляется при завершении сессии scutil. PF — механизм текущего preview, не публичный API Apple; для распространения и строгих системных гарантий нужен переход к Network Extension ([Apple TN3165](https://developer.apple.com/documentation/technotes/tn3165-packet-filter-is-not-api)). Правила других PF/WFP-провайдеров при recovery не удаляются; включение PF сбрасывает существующие состояния соединений для исключения обхода новой политики.

Android удерживает дополнительный TUN-дескриптор, чтобы отказ запуска Go-стека не возвращал сеть напрямую. При ручном выключении без lockdown интерфейс закрывается. При включённом lockdown интерфейс остаётся, но все соединения идут через прямые `protect()`-сокеты без VPN-сервера; системный значок VPN может оставаться. Системную блокировку приложение не снимает.

**Для защиты Android при завершении всего процесса необходимы «Постоянная VPN» и «Блокировать соединения без VPN».** Обычное приложение не может включить эти настройки самостоятельно. Отзыв разрешения/снятие блокировки пользователем меняет системные гарантии ([Android VPN](https://developer.android.com/develop/connectivity/vpn)).

Нативные сценарии crash, сон/пробуждение, смена интерфейса, обновление и трафик IPv4/IPv6 требуют проверки на целевых ОС. Unit-тесты и кросс-сборка не подтверждают отсутствие пакетов на физическом интерфейсе. До старта системной защиты при загрузке ОС и при её административном отключении гарантий нет.

## DNS и атрибуция

TUN перехватывает обычный DNS TCP/UDP 53, выдаёт Fake-IP для A/AAAA с TTL 0 и сохраняет соответствия. Неизвестные Fake-IP никогда не отправляются напрямую. DoH/DoT и встроенные IP могут скрывать домен: доменное правило не покрывает нераспознанный IP автоматически. Доверие приложению работает при успешной идентификации владельца ОС; неподдерживаемая или неудачная атрибуция не может безопасно приписать поток другому приложению. В выборочном режиме без идентификации приложения общие правила IP/доменов не дают VPN-доступ. Полный режим — отдельное явное разрешение всему устройству. В выборочном режиме MX/TXT/SRV не пересылаются. В полном режиме обычный DNS TCP/UDP 53 передаётся через VPN по TCP с ограничением времени и числа запросов; публичный DNS назначения сохраняется, виртуальный/локальный резолвер заменяется на `1.1.1.1` на выходе VPN. Поддерживаются исходные типы записей, включая HTTPS/ECH. Положительные A/AAAA заменяются на сохранённые Fake-IP: конечное доменное имя передаётся VPN-серверу, который выбирает рабочее семейство адресов. NXDOMAIN/NODATA сохраняются. Ответы имеют TTL 0; UDP-ответ ограничен EDNS-размером (не более 4096 байт), с TC для повторения по TCP. Прямого DNS-резерва нет.

Публичные суффиксы, wildcard, URL, порт и CIDR не принимаются как разрешения. Домены сравниваются по границе DNS-меток с IDNA. Серверный Xray по умолчанию блокирует неразрешённый трафик, внутренние сети, localhost, metadata, link-local и переходные IPv6-префиксы.

## Сервер и инфраструктура

REALITY защищает клиентский канал, собственный HTTPS-домен не требуется. API использует TLS 1.3 с закреплением SPKI публичного ключа. В коде включён `InsecureSkipVerify` только вместе с обязательным `VerifyConnection`, проверяющим ключ и срок сертификата; пустой/чужой pin отклоняется. Перенаправления HTTP запрещены.

Вход пользователей выполняется по случайным 256-битным ключам `lnv_…`; сервер хранит только их SHA-256, как и хэши токенов устройств и одноразовых кодов привязки (256 и 120 бит). Логин — несекретное имя аккаунта. Старые bcrypt-хэши не принимаются для входа и удаляются из текущего состояния БД при открытии/обновлении; исторические страницы bbolt и резервные копии очищаются отдельным жизненным циклом хранения. Пользовательская замена ключа требует текущий личный ключ и отзывает все устройства и коды аккаунта; сохранённые правила остаются. Админ-пароль задаётся через Ansible Vault/секрет деплоя, на сервере хранится только bcrypt-хеш в root-owned файле 0640; сессия администратора живёт восемь часов и хранится в памяти. Штатный деплой включает `public_admin`: страница входа админки доступна по публичному HTTPS на 8443. Данные и административные действия требуют сессии администратора; токены устройств её не заменяют. Проверка Origin, лимиты входа по IP/IPv6 /64 и общий лимит действуют также на публичном listener. Без `public_admin` административные маршруты публично отсутствуют; локальный listener остаётся на loopback. Admin/API не используют cookies, все изменения требуют bearer-токен. Пароли и ключи не пишутся в access log; журналы посещений Xray отключены. База хранит разрешения и очередь запросов, поэтому резервные копии конфиденциальны.

Общий профиль `linevpn://…?pin=…&access=…` содержит случайный ключ подключения. Он требуется для регистрации, входа нового устройства и использования кода привязки через заголовок `X-LineVPN-Profile`; одного профиля недостаточно для доступа к аккаунту/VLESS. Ключ профиля хранится в серверной БД с правами 0600, чтобы администратор мог повторно экспортировать текущий профиль. Перевыпуск атомарно меняет его и отзывает коды привязки. Уже подключённые устройства сохраняют доступ, если администратор явно не выбрал их отзыв. TLS/REALITY private keys эта ссылка не содержит. Утечка приватных ключей сервера или диска VPS требует отдельного восстановления доверия; замена ссылки её не устраняет.

VPS-провайдер всё равно может видеть IP-адреса, объём и время соединений; оператор гипервизора потенциально видит память/диск VM. Исходящий HTTP к сайту не шифруется магически после выхода из VPN. Ни REALITY, ни этот проект не обещают невидимость для владельца VPS или защиту от компрометации серверной ОС.

## Локальное управление desktop

Начиная с 0.3.0, доступный локальным пользователям `ui-token` разрешает только чтение состояния и создание ожидающего запроса. Сам по себе он не позволяет входить в аккаунт, выдавать разрешения, менять режим или выключать VPN. Прямой POST к прежнему `/local/*` API возвращает 403. Состояние, список приложений и история наблюдений остаются доступны пользователям машины с этим токеном; это не изоляция их диагностических данных.

Изменение выполняет установленный помощник после Windows UAC / административного подтверждения macOS и отдельного показа конкретного действия. Окно берёт описание из неизменяемого запроса службы; отмена выбрана по умолчанию. Секреты и профиль не передаются в аргументах запуска. В командной строке находится только случайный идентификатор, который сам по себе не разрешает выполнение. Подтверждение одноразовое, связано с содержимым запроса и истекает через три минуты; очередь ограничена 16 запросами. Старое подтверждение нельзя повторить после перезапуска службы.

Административный токен и адрес закрытого канала хранятся в `control/session.json`: каталог 0700 и файл 0600 на macOS, защищённый DACL только для SYSTEM/Administrators на Windows. UI их не получает. Оба loopback-канала используют TLS 1.3: UI доверяет только сертификату из служебного `ui-session.json`, помощник проверяет закреплённый SPKI. Сертификат и административный токен создаются заново при старте службы. Подставная служба на прежнем порту не должна получить ключ входа или профиль. UI загружается из установленного пакета, удалённая навигация и чужие IPC-вызовы запрещены; перехода к HTTP при ошибке нет.

Это разделяет обычные локальные приложения и управление политикой. Root/Administrator, скомпрометированная служба и выданное пользователем системное разрешение остаются за границей этой защиты. Локальное приложение может заполнить очередь или занять порт, вызвав отказ в обслуживании, но не получить разрешение на VPN. При обновлении нужны согласованные версии агента и desktop UI из одного установщика. Подробности и пределы проверки: [ревью локального управления](desktop-control-review-2026-11-23.md).

## Получатель и режим всего трафика

Туннель переносит байты TCP и UDP без HTTPS MITM, подмены сертификатов или добавления `Via` / `Forwarded` / `X-Forwarded-For`. TLS клиента к сайту остаётся внутри туннеля; fingerprint `chrome` относится к внешнему REALITY-соединению с VPN-сервером. Это не делает IP VPS домашним IP: получатель видит выходной IP, может определить хостинг/ASN, а также сопоставлять браузерные идентификаторы, аккаунт, географию и время соединений. Маскировка канала REALITY не гарантирует невидимость для сайта.

Полный режим не разрешает обход серверного запрета private/loopback/metadata/reserved egress. LAN-запросы не возвращаются напрямую. Служебные соединения к VPN-серверу и API должны идти по физической сети, иначе возникнет петля. TUN поддерживает TCP/UDP IPv4/IPv6; неподдерживаемые протоколы отклоняются. Loopback и системные исключения нативного firewall не превращаются в удалённый VPN-трафик.

После явного возврата из полного в выборочный режим снова действуют ограничения распознавания доменов: собственный DNS/DoH-кэш приложения и встроенные IP могут скрывать домен. Для защиты всего трафика приложения используйте доверие приложению; для всего устройства — полный режим. TTL 0 ограничивает кэширование обычного DNS, но не управляет внутренним кэшем сторонних приложений.

Локальные разрешения проверяются по владельцу сокета, определённому ОС. Это не sandbox для кода с root/Administrator, доступа к памяти/ключам службы или административному локальному UI-token. Desktop preview использует общий UI-token машины: такой локальный субъект способен изменить политику, поэтому защита от враждебного кода с доступом к этому токену требует отдельной изоляции IPC/учётных записей. Обычное сетевое соединение не получает доверие по одному совпадению адреса.

## Устойчивость управления и хранения

Лимиты входа объединяют IPv6-адреса по /64, имеют жёсткий предел 8192 счётчика и отклоняют новые ключи при заполнении. Для администратора действует также общий лимит; discovery ограничен по устройству. Неодобренные регистрации ограничены 200 одновременно и удаляются через 7 дней; отозванные устройства очищаются через 30 дней. Массовый отзыв требует ввода `REVOKE-ALL`.

Состояние bbolt кэшируется в памяти; View возвращает глубокую копию, проверка bearer использует индекс хешей устройств. Ошибка записи не публикует кэш и индекс. Некорректный кандидат Xray отклоняется до commit. При ошибке применения уже записанной конфигурации транспорт закрыт, сервер повторяет последнюю конфигурацию и не возвращает отозванные credentials. Одноразовые результаты ротации/привязки не теряются из-за ошибки транспорта. Хранилище всё ещё записывает один JSON-объект при реальном изменении; миграция на отдельные buckets требует отдельной работы.

Секретные файлы получают 0600 на Unix и защищённый DACL (SYSTEM, Administrators, текущий пользователь процесса) на Windows. Существующие файлы проверяются и ужесточаются при чтении. Unix-реализация fsync-ит каталог после rename; Windows не даёт той же гарантии через directory fsync. Unix-каталоги, записываемые другими пользователями, и symlink-каталоги состояния отклоняются. Windows-защита каталога desktop-службы остаётся обязанностью установщика и control bridge. Форматирование Profile и slog скрывают его поля; явная JSON-сериализация по авторизованному API по-прежнему содержит необходимые секреты.
