## Разрешённые пересечения

- Совмещены поля состояния, предупреждения о несохранённых правилах, диагностике соединений, отсутствии связи с API и системной защите Android.
- Из PR #22 сохранено отсутствие искусственного обрыва молчащих VPN-потоков. EOF после реальной отправки без ответа остаётся диагностируемой ошибкой, EOF неиспользованного потока — обычным завершением. Регрессия #21 адаптирована к этому контракту и выполняет реальную запись перед EOF.
- Ошибка API не закрывает рабочие соединения; 401/403 очищают ключи. Ни ошибка, ни диагностический кэш не разрешают прямой маршрут защищённого трафика. Правила, полученные из аккаунта, также учитываются при закрытии затронутых потоков.
- Installer hooks сохраняют PF/WFP при обновлении. Из #23 сохранены проверка отсутствующего/оставшегося worker, отказ второго экземпляра, реальная повторная установка, проверка подписанного APK на границе публикации и проверки сохранения данных.
- Общая версия 0.2.1, Android versionCode 2001. Единственный источник версии — package.json; сертификат берётся из текущего manifest. MSI одной версии использует repair, новой — MajorUpgrade. macOS устанавливает app и службу одним PKG.
- PR не получают пароли подписи, собирают только тестовый debug APK и не публикуют current. Main требует прежний ключ. Некорректная подпись или неполный installer payload отклоняются до удаления прежних файлов current.

## Ограничения и внедрение

GitHub Actions у исходных пяти PR показывают failure для test и skipped для платформенных сборок/публикации; успешного удалённого прогона нет. Причина отказа доступным API не установлена. Перечисленные успешные проверки выполнены локально.

Нативная установка прежний опубликованный пакет → новый, MSI rollback, PF/WFP packet capture, сон/смена сети, Android lockdown и смерть процесса на реальных устройствах не подтверждены. Linux-кросс-сборки и тесты логики не заменяют эти проверки. Старый установленный MSI/supervisor может выполнить собственный recovery при обновлении; новый пакет не переписывает уже запущенный старый код.

Для сохранения правил из #20 сначала обновить сервер, затем клиенты и дождаться синхронизации перед удалением данных. Слияние исходников не обновляет работающий VPS или уже скачанные установщики. Существующий manifest остаётся привязан к прежней сборке; новый комплект требует отдельной сборки и нативной приёмки.
