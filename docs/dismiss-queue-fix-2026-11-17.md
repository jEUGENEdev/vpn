# Исправление «Оставить напрямую» — 17 ноября 2026

Ошибка воспроизведена через HTTP API: при 1000 наблюдениях `/api/dismiss` для `whatsapp.net` возвращал 500 «очередь адресов заполнена», если в очереди был только поддомен либо адрес ещё оставался локальным. Сохранённые решения также вытесняли новые наблюдения.

Теперь лимиты наблюдений и решений считаются отдельно (по 1000 на аккаунт). Родительское решение освобождает записи поддоменов; чужие аккаунты, другие наблюдения, прежние решения и VPN-разрешения сохраняются. Повторное решение идемпотентно. Отдельный лимит решений возвращает 409 с объяснением. Формат базы и API не менялся, миграция или сброс профиля не требуются.

До исправления новые `TestDismiss*` падали с исходной ошибкой. После исправления пройдены `go test -race -tags with_gvisor ./internal/server ./internal/store ./internal/client ./internal/policy`, `go vet` этих пакетов, Linux-сборка `cmd/linevpn-server` и `git diff --check`. Тесты проверяют полную очередь с активными сбоями, группировку, локальный адрес, независимые лимиты, повторный выбор, сохранение после повторного открытия базы, синхронизацию двух устройств и изоляцию аккаунтов.

**Нужно обновить сервер.** Установщики клиентов не включают серверный обработчик; совместимые клиенты получают исправленное поведение после обновления бэкенда. Деплой на реальный VPS в ходе этой проверки не выполнялся. Обновление описано в [deployment.md](deployment.md); существующие ключи и база сохраняются.
