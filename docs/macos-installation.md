# Установка и диагностика macOS

Для Apple Silicon выбирайте `macos-arm64.dmg`, для Intel — `macos-x64.dmg`. Сначала сверяйте `manifest.json`: версия и `source_commit` относятся именно к лежащему рядом файлу, а не к последнему изменению исходников.

## Установка поверх прежней версии

В сборках из исходников **0.2.1 и новее** откройте `Install-LineVPN.pkg` внутри DMG. Он обновляет приложение в `/Applications` и службу одним запуском, сохраняя `/var/lib/linevpn` и настройки Electron. Предварительная деинсталляция не нужна. Старые процессы завершаются до замены файлов; установка более старой версии отклоняется. Затем откройте приложение из «Программ».

Повторный запуск того же PKG выполняет повторную установку текущей версии с сохранением данных. Если установка прервалась, повторите запуск этого PKG; при сбое после остановки службы автоматический откат всей macOS-установки не гарантируется. [Сценарии проверки](installer-upgrade.md) отдельно отмечают нативные проверки, которые ещё нужно выполнить.

В **уже опубликованных DMG 0.2.0** остаются два шага: заменить `LineVPN.app` в `/Applications`, затем установить `Install-LineVPN-Service.pkg` из того же DMG. Одно перетаскивание приложения не обновляет службу. Изменение исходников не меняет скачанные DMG.

## Если macOS пишет «файл повреждён»

1. Проверьте скачанный файл. Актуальные ссылки находятся в [installers/current](../installers/current/). Для ручной сборки от 17 ноября 2026 скачивайте DMG из **Assets релиза**, указанного в manifest. Установщики из прежних коммитов хранятся через Git LFS: указатель около 130 байт с первой строкой `version https://git-lfs.github.com/spec/v1` — это текст, а не DMG; для таких старых файлов нужны **Download raw file** или `git lfs pull`. Сверьте размер и SHA-256 именно с manifest выбранной сборки.
2. Выполните `shasum -a 256 /путь/к/LineVPN.dmg` и сравните результат с `SHA256SUMS`. Затем `hdiutil verify /путь/к/LineVPN.dmg`. При несовпадении скачайте образ заново. Не снимайте защиту с действительно повреждённого файла.
3. Если образ монтируется, а ошибка возникает при открытии `LineVPN.app`, проверьте установленное приложение: `codesign --verify --deep --strict --verbose=2 /Applications/LineVPN.app`. В старом DMG 0.2.0 сначала скопируйте приложение в `/Applications`; в новом комплекте оно устанавливается через `Install-LineVPN.pkg`. Ошибка подписи означает, что нужна пересборка/повторная загрузка, а не изменение глобальных настроек безопасности.
4. `spctl --assess --type execute --verbose=2 /Applications/LineVPN.app` проверяет доверие Gatekeeper отдельно от целостности. Preview без нотарификации может быть заблокирован даже при правильной ad-hoc подписи. Для проверенного вами preview используйте предусмотренное macOS подтверждение в **Системные настройки → Конфиденциальность и безопасность → Всё равно открыть**, если оно доступно. Не отключайте Gatekeeper глобально и не удаляйте quarantine автоматически.
5. Повторно установите PKG из того же образа (`Install-LineVPN.pkg` для нового комплекта, `Install-LineVPN-Service.pkg` для старого 0.2.0), затем откройте приложение. Если GUI просит службу, посмотрите `/var/log/install.log` и `/var/log/linevpn-error.log`.

Для новой версии 0.2.1 запустите единый `Install-LineVPN.pkg`: он обновляет приложение и службу вместе. Старый интерфейс и worker останавливаются до замены файлов; профиль, правила и режим VPN сохраняются. Для опубликованной 0.2.0 действуют два шага, описанные выше. [Проверка обновления](installer-upgrade.md).

В прежнем workflow было `CSC_IDENTITY_AUTO_DISCOVERY=false` без явной ad-hoc подписи. Установка службы проверялась, а финальный DMG и запуск Electron — нет. Это подтверждённый пробел сборки; без проблемного файла и лога с Mac нельзя утверждать, какой именно из перечисленных случаев вызвал конкретное сообщение.

## Сборка preview

Ручная Linux-кросс-сборка от 17 ноября 2026 опубликована отдельно от CI; описанные ниже нативные проверки на Mac для неё не выполнялись. Выполненные проверки и ограничения записаны в [отчёте текущей сборки](manual-build-network-fix-2026-11-17.md).

На macOS с Go и Node запустите `scripts/package-macos.sh arm64` или `scripts/package-macos.sh amd64`. Скрипт явно подписывает Go-агент и Electron ad-hoc, сохраняет hardened runtime и задаёт entitlements для JIT и загрузки Electron Framework без общего Team ID. После упаковки он проверяет подпись и архитектуру приложения/агента непосредственно из готового DMG. Такой preview не считается нотарифицированным релизом.

CI дополнительно устанавливает **PKG из проверенного DMG**, запускает установленный им GUI и проверяет загрузку клиентского интерфейса. В сценарий включена повторная установка с проверкой сохранения профиля, токена и решений приложений. Результаты: `macos-signing.txt`, `macos-gui.txt`, `macos-native.txt` в артефактах соответствующей архитектуры. Эти проверки считаются пройденными только после успешного выполнения соответствующего job, а не по наличию сценария в репозитории. Установщики публикуются только после успешных проверок всех платформ.

## Подписанный релиз

На машине сборки должны быть доступны приватные ключи сертификатов **Developer ID Application** и **Developer ID Installer**, а учётные данные нотарификации должны быть сохранены в Keychain через `xcrun notarytool store-credentials`. Сертификаты и пароли не помещаются в репозиторий.

```bash
export LINEVPN_MACOS_SIGNING=release
export LINEVPN_MACOS_APP_IDENTITY='Developer ID Application: Your Name (TEAMID)'
export LINEVPN_MACOS_INSTALLER_IDENTITY='Developer ID Installer: Your Name (TEAMID)'
export LINEVPN_MACOS_NOTARY_PROFILE='linevpn-notary'
scripts/package-macos.sh arm64
```

Скрипт подписывает агент и PKG, нотарифицирует и прикрепляет ticket к PKG; hook `afterSign` нотарифицирует приложение и прикрепляет ticket **до** создания DMG. Затем подписывается, нотарифицируется и проверяется сам DMG. Отсутствие параметров, неуспешная подпись, нотарификация или проверка завершают сборку ошибкой; молчаливого перехода к неподписанному release нет. Этот режим рассчитан на локальный/защищённый macOS runner с настроенным Keychain; обычный workflow PR собирает preview и не получает release-ключи.

Подпись релиза требует реальных сертификатов владельца проекта. До запуска на Mac, проверки Gatekeeper на скачанном файле с quarantine и успешной сборки новые установщики не считаются проверенными. Опубликованные DMG не меняются от редактирования скриптов; исходный коммит каждой сборки указан в manifest.

Источники: [electron-builder v26: macOS signing](https://www.electron.build/v26/docs/features/code-signing/code-signing-mac/), [Apple: безопасное открытие приложений](https://support.apple.com/102445).

## Удаление и доступность сети

В новой сборке используйте **«Удалить Линию VPN»** из трея или `Uninstall-LineVPN.command` из DMG. Утилита останавливает LaunchDaemon, восстанавливает остатки DNS/PF старой версии и только затем удаляет helper и приложение. Профиль сохраняется. Ошибка восстановления останавливает удаление.

Удаление уже обнаруженного `/Applications/LineVPN.app` в корзину отключает сетевую службу после 30 секунд отсутствия; оставшиеся служебные файлы удаляются утилитой. При включённом VPN новые сессии сохраняют PF-блокировку до явного выключения или удаления; сбой worker её не снимает. Старой установке нужна новая сборка или [ручное восстановление](network-recovery.md).
