# Защищённые сервисы при сбоях VPN

> Этот раздел описывает исходные сетевые гарантии. Для установщиков 0.4 действует [полное удаление и чистая установка](installer-upgrade.md); прежние upgrade/recovery-сценарии больше не предлагаются.

Основа изменения: `main` / `20a5a9115bf1a9d770e31871ebfe52957b34c1d1`, 17 ноября 2026.

Пока включён VPN, сохранённые адресные разрешения, ожидающие подтверждения разрешения и доверенные приложения не имеют прямого резерва. Потеря API, отозванный ключ, отсутствие app-credential, неудачный dial, TCP/UDP read/write и таймаут не меняют это правило. Прямой доступ для защищённых сервисов появляется после явного выключения. Пользователь также может явно удалить отдельное разрешение или отозвать доверие приложению.

Общий код применяется ко всем клиентам. Исправлена также гонка обновления профиля: если настройка нового транспорта не удалась, уже открытый прямой поток к вновь защищённому адресу закрывается.

Windows и macOS сохраняют постоянный firewall при crash/restart worker и обновлении. Если нет работающего TUN, блокируется весь пользовательский исходящий трафик; его безопасная классификация требует работающего агента. Cleanup при установке/обновлении больше не отключает защиту. Явный uninstall/recovery остаётся административным восстановлением сети.

Android сохраняет дубликат TUN при ошибке Go-стека. Lockdown совместим с кнопкой off: TUN остаётся, но весь трафик направляется через прямые сокеты, без VPN-сервера. Защита при смерти процесса требует системных настроек «Постоянная VPN» и «Блокировать соединения без VPN». Приложение само их не включает.

## Проверка

- `go test -tags with_gvisor ./...` — общий Go-код, транспорт, сервер и мобильная граница.
- `go test -race -tags with_gvisor ./internal/client ./internal/platform ./mobile` и `go vet -tags with_gvisor ./...`.
- Регрессии проверяют отсутствие вызова прямого socket-control для TCP/UDP, IPv4/IPv6 и доменов при разных видах защиты, повторных попытках и очистке диагностического кэша. После off прямой socket-control вызывается.
- Проверены офлайн-запуск, сохранённый off/on, просроченная авторизация, неподтверждённое доверие, закрытие старого прямого потока при неудачном обновлении, read/write/timeout, ограничение уведомлений и диагностического кэша.
- Нативный выбор startup/recovery проверяется отдельно: только `vpn_disabled: true` снимает защиту; отсутствие/повреждение файла или ошибка guard не вызывают recovery.
- DOM-тест проверяет предупреждения, частичный сбой и доступность кнопки выключения при ошибке запуска. Проверка упаковки запрещает recovery во время MSI upgrade.

- Агент собран с `with_gvisor` для Windows amd64 и macOS arm64. Android: `gomobile bind` arm64 и Gradle `:app:assembleDebug` прошли; проверена совместимость Kotlin/JNI.
- Android instrumentation-тест не запускался: зависимости AndroidX Test/JUnit отсутствуют в офлайн-кэше. Нативные Windows/macOS сценарии также не запускались на этом Linux-хосте.

## Границы

Кросс-компиляция не заменяет захват пакетов на настоящих Windows/macOS/Android. Требуются проверки PF/WFP, IPv6, существующих потоков, изменения интерфейса, сна, обновления и Android lockdown. PF текущего macOS preview не является публичным API Apple. До запуска защиты ОС, при административном отключении firewall или снятии разрешения VPN абсолютных гарантий нет. Неизвестные домены за DoH/DoT и нераспознанные владельцы потоков ограничивают применимость адресных и приложенческих правил; подробности в [security.md](security.md).

Изменение защиты само по себе не меняет серверный протокол. В объединённом наборе PR #20 добавляет сохранение правил в аккаунте: сначала обновите сервер, затем клиенты. Существующий релиз не содержит это изменение; VPS и опубликованные установщики этой правкой не обновлялись.
