# Повторная установка и обновление

Проверены исходники `main` на `20a5a9115bf1a9d770e31871ebfe52957b34c1d1` и метаданные опубликованных MSI/APK из `v0.2.0-preview.20261117.4`. Проверка: 17 ноября 2026. Исправления ниже относятся к новым исходникам 0.2.1, а не к уже опубликованным файлам 0.2.0.

## Обнаруженные проблемы

| Платформа | Поведение 0.2.0 | Исправление в исходниках 0.2.1 |
| --- | --- | --- |
| Windows | UpgradeCode стабилен, данные вне payload; обновление предусмотрено. Но опубликованный MSI выполняет RemoveExistingProducts на шаге 1401, до InstallInitialize (1500): при ошибке установки старая версия может остаться удалённой. | MajorUpgrade после InstallInitialize; старый payload удаляется внутри транзакции, допускающей откат. Сохраняются UpgradeCode, служба и каталог данных. |
| macOS | PKG заменяет файлы агента и его shell-supervisor, затем останавливает службу в postinstall. Однократная проверка launchd может ошибочно считать асинхронную остановку неудачной. | preinstall останавливает службу и ждёт исчезновения задания/worker до 30 секунд до замены payload. Если остановка не удалась, установка прекращается. postinstall запускает один новый экземпляр. |
| Android | ID приложения стабилен, но CI использует автоматически созданный debug-ключ нового runner. Такой APK может иметь другую подпись и не обновит установленный. versionCode всех сборок равен 2. | Сохранён ID, versionCode повышен до 3. Сборка для распространения и публикация проверяют подпись, applicationId и версию готового APK. Несовпадение блокирует публикацию. |

Во всех трёх случаях обновление должно сохранять `profile.json` (включая устройство, авторизацию, адресные правила, ожидающие решения и выключенное состояние VPN), `applications.json` и остальные пользовательские данные. Windows хранит их в `%ProgramData%\LineVPN`, macOS — `/var/lib/linevpn`, Android — в приватном `filesDir` приложения. Эти каталоги не являются заменяемыми файлами desktop-установщика; Android сохраняет их при установке совместимого APK поверх прежнего.

## Как устанавливать поверх

- **Windows:** запустить новый MSI. Он использует прежний UpgradeCode и заменяет зарегистрированную установку. Повторный запуск того же самого MSI — обслуживание/восстановление той же установки; отдельная копия приложения не создаётся. Пересобранный MSI с другим ProductCode и той же версией также обрабатывается как MajorUpgrade.
- **macOS:** завершить интерфейс через трей, заменить `LineVPN.app` в «Программах», затем запустить `Install-LineVPN-Service.pkg` из того же нового DMG. Открыть приложение после завершения Installer. Служба устанавливается отдельно: одной замены `.app` недостаточно.
- **Android:** открыть новый APK и подтвердить обновление либо выполнить `adb install -r <apk>`. Не удалять старое приложение и не выполнять `pm clear` для обхода ошибки подписи: это удалит локальные данные. Для обновления нужен исходный ключ подписи.

Режим выключенного VPN сохраняется. Обновление работающего VPN предполагает перезапуск службы и может прервать соединения. Новые installer hooks не вызывают явный `recover-network` на пути обновления. Однако старый MSI/старый macOS supervisor могут выполнить свой recovery при удалении/остановке; изменить уже установленный uninstall-код задним числом новым условием нельзя. Этот PR не заменяет отдельную работу над fail-closed и не подтверждает отсутствие прямого трафика при обновлении старых клиентов.

## Версии и подпись

`apps/desktop/package.json` задаёт общую версию Electron/MSI/PKG/APK, Android versionCode и ожидаемый SHA-256 сертификата. Для каждого нового выпуска нужно увеличивать `version` и `linevpn.androidVersionCode`, синхронизировать версию в package-lock. Нельзя различать разные выпуски только именем файла или git SHA. Начальная версия этих изменений: `0.2.1`, Android `3`, имя `0.2.1-preview`.

Закреплён сертификат уже опубликованного ручного APK:

`b13dfe366940dc70d27e244c8bf17ed18ff3dfdad93713bdbc1b91cbfa85f0b1`

Для CI на main нужен секрет `ANDROID_PREVIEW_KEYSTORE_BASE64` с **существующим** preview-keystore (стандартные debug alias/password). Здесь секрет не создавался и не менялся. Для локальной сборки этот же keystore можно передать через `ANDROID_DEBUG_KEYSTORE`. Создание нового ключа или изменение закреплённого fingerprint не сделает обновление старых APK совместимым. Если ключ потерян, гарантировать обновление существующих установок нельзя.

Сборка `LINEVPN_ANDROID_TEST_ONLY=1` допускает временный debug-ключ только для тестов. PR собирают тестовые артефакты без release-секретов и не обновляют `installers/current`. Публикация повторно проверяет APK независимо от флага сборки; для проверки требуются JDK и Android build-tools 35.0.0. Ручные упаковщики также должны запускать `scripts/verify-android-update.py`; опция `--previous <apk>` дополнительно сравнивает новую сборку с конкретным предыдущим APK.

## Проверки и границы

`python3 scripts/test-network-packaging.py` проверяет сгенерированный WiX: остановку службы, условие recovery, обновление той же версии и транзакционный порядок. `python3 scripts/test-installer-update.py` проверяет стабильность идентификаторов, версии, отказ при неправильной подписи и исполняет macOS hooks с изолированными подменами системных команд. Проверяются повторная установка, асинхронная остановка, зависший процесс, запрет второго экземпляра, ошибка запуска и сохранение файлов данных.

В нативные CI-сценарии добавлены:

- Windows: восстановление того же MSI, обновление другим MSI с новым ProductCode, замена/удаление файлов payload, запуск службы и сохранение profile/applications/ui-token и состояния устройства.
- macOS: две последовательные установки PKG поверх работающей службы с сохранением данных и режима VPN.
- Android: две установки APK поверх заполненных profile/applications без очистки данных между ними.

Локальные тесты hook-логики и метаданных не заменяют установку на Windows/macOS/Android. Нативные сценарии не исполнены в Linux-среде этой проверки. Требуются приёмка предыдущий опубликованный пакет → новый пакет и повторная установка на каждой ОС, включая сбой установки, перезагрузку и packet capture. Наличие транзакции MSI не является проверкой всех системных побочных эффектов rollback. macOS PKG не обещает транзакционный откат при ошибке postinstall: профиль сохраняется, но службе может потребоваться повторная установка.

Выполнено локально: 10 тестов `test-installer-update.py`, `test-network-packaging.py`, синтаксическая проверка Bash/PowerShell/Python и workflow YAML. `:app:assembleDebug --offline` успешно проверил новую Gradle-конфигурацию и Kotlin-код с ранее собранным `core.aar`; Go/AAR в рамках этой проверки не пересобирался. У полученного тестового APK проверены подпись, package ID, versionCode 3 и совместимость с сертификатом опубликованного APK. Эта тестовая сборка не опубликована как новый комплект установщиков.

Источники поведения платформ: [WiX MajorUpgrade](https://docs.firegiant.com/wix/schema/wxs/majorupgrade/), [Android app signing](https://developer.android.com/studio/publish/app-signing), [Android versioning](https://developer.android.com/studio/publish/versioning).
