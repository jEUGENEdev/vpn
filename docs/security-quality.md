# Проверки безопасности и качества

Практики адаптированы к LineVPN: правила для агентов находятся в `AGENTS.md`,
автоматические проверки — в `scripts/check.sh` и `scripts/check-security.sh`.
Рабочая модель угроз — [threat-model.md](threat-model.md). Эти файлы не являются
заключением о безопасности всех компонентов или реального VPS.

Первый прогон: [отчёт от 17 ноября 2026](security-quality-review-2026-11-17.md).
Исправления, повторные проверки и ограниченное исключение сборочной зависимости:
[отчёт от 18 ноября 2026](security-quality-review-2026-11-18.md).

DNS, обновление REALITY-профиля и IPv6 egress:

## Подготовка локальных проверок

Нужны Go 1.27.4, Node 24 с npm, Python 3.12+, Bash, Git и OpenSSH client.
Проверки выполняют локальные fixtures и не требуют VPS, паролей или ключей подписи.

```sh
python3 -m venv build/check-env
. build/check-env/bin/activate
python3 -m pip install -r tools/checks/requirements.txt
npm ci --prefix tools/ui-tests --ignore-scripts --no-audit --no-fund
npm ci --prefix apps/desktop --ignore-scripts --no-audit --no-fund
tools/ui-tests/node_modules/.bin/playwright install chromium
bash tools/checks/install.sh
export PATH="$(go env GOPATH)/bin:$PATH"
```

На минимальном Linux для Chromium также нужны системные зависимости:
`tools/ui-tests/node_modules/.bin/playwright install --with-deps chromium`.
Установка инструментов и браузера требует сети. Проверки не устанавливают их
автоматически и не изменяют правила сети/службы хоста.

## Общий прогон

```sh
bash scripts/check.sh
bash scripts/check-security.sh
```

| Команда | Что подтверждает |
| --- | --- |
| `bash scripts/check.sh go` | gofmt, целостность модулей, полный Go-прогон с race detector и `with_gvisor`, vet |
| `bash scripts/check.sh portable` | синтаксис JS/shell, сгенерированный MSI, macOS installer fixtures, версии, ручной деплой и SSH на loopback |
| `bash scripts/check.sh ui` | DOM и браузерные сценарии настоящего клиентского/административного UI |
| `bash scripts/check.sh desktop` | Ограниченное по времени воспроизведение glob DoS и фильтрация файлов настоящим matcher Electron builder |
| `bash scripts/check-security.sh` | синтаксис Actions, поиск секретов с редактированием значений, локальный поиск Go/npm/Python по OSV и анализ достижимости Go через govulncheck |

`check.sh` без аргументов запускает все четыре группы. Нативные smoke-тесты не входят
в безопасный локальный прогон: они устанавливают службы и меняют сеть на
одноразовых Windows/macOS/Android runners. Сборка с Linux не заменяет их.
Для изменений сети нужны также сценарии из [acceptance.md](acceptance.md),
включая наблюдение IPv4/IPv6-трафика при сбоях, обновлении и ручном off.

OSV-Scanner скачивает целые публичные базы Go/npm/PyPI и сравнивает версии
локально с `--offline`. Дерево зависимостей приватного репозитория не отправляется
в registry audit, OSV API или deps.dev. Включены devDependencies: Electron и
сборочные инструменты находятся именно там. При недоступной базе проверка
завершается ошибкой. Находка по версии требует проверки достижимости и влияния;
OSV не анализирует call graph. Дополнительно запускается закреплённый `govulncheck v1.10.0` с `with_gvisor`. Python lockfile деплоя включает транзитивные зависимости и wheel-хеши. Эти проверки не заменяют аудит ОС, Android SDK и нативного поведения. Любая находка блокирует gate до
исправления или узкого, обоснованного исключения с датой пересмотра.

Базы обновляются в каждом прогоне. Для среды без сети предварительно скачайте
те же базы и запускайте команду OSV из скрипта без `--download-offline-databases`.
Подробности: [официальный offline mode](https://google.github.io/osv-scanner/usage/offline-mode/).

Gitleaks в общем прогоне сканирует текущее дерево, включая новые файлы, с
редактированием найденных значений. Кроме стандартных правил проверяются
ключи аккаунта `lnv_…` и секрет `access` в экспортированном профиле; отдельный тест
проверяет обнаружение и редактирование синтетических ключей. Это не проверка всей истории Git. Историю
проверяют отдельно в полном клоне командой
`gitleaks git . --redact --config .gitleaks.toml --log-opts="--all"`.

## CI

`build.yml` вызывает reusable `security.yml` перед тестами и сборками.
`deploy.yml` требует его успеха перед шагами с VPS-секретами. Проверки не
наследуют секреты и не вызывают LLM API. Все внешние Actions закреплены SHA.
UI-тесты используют отдельный lockfile и `npm ci --ignore-scripts`.
Dependabot предлагает обновления Actions, Go, npm и Python зависимостей;
автоматическое слияние не включено.

Защита `main` настраивается в GitHub отдельно. При её включении сделайте
обязательными Go/UI-тесты и security job из PR workflow. В этой правке настройки
branch protection не изменяются. При исчерпанном лимите Actions нужно приложить
результаты локальных проверок и отдельно отметить непроверенные нативные задачи;
это не означает, что удалённый CI прошёл.

## Ревью изменения

Для рискованного изменения запишите границу доверия, исходный сценарий сбоя,
какие callers/платформы затронуты, сохранённый инвариант и тест, который ловит
регрессию. Проверьте весь итоговый diff отдельным проходом. Не называйте этот
проход независимым ревью другого агента/человека, если его не было.

| Изменение | Вопросы ревью |
| --- | --- |
| Fail-closed и power | Может ли retry, EOF, таймаут, ошибка sync/запуска или upgrade открыть direct? Закрываются ли старые потоки? |
| Авторизация | Может ли старый токен, чужое устройство, одинаковое имя или гонка с отзывом изменить данные? Отозваны ли оба Xray credential? |
| TLS/egress | Сохранились ли SPKI, срок сертификата, запрет redirect, private/metadata IPv4/IPv6 и неизвестных Fake-IP? |
| Хранение | Не теряется ли решение после ошибки записи, рестарта, переустановки или совместной работы устройств? |
| Установщик | Установка поверх отклонена? Удаление очищает локальную идентичность после остановки службы? Сохранена подпись? Ошибка cleanup видна? Чужие настройки сети не удалены? |
| UI/IPC | Данные домена/приложения не становятся HTML/командой? Токен не попадает в URL/логи? Есть ли понятная ошибка и рабочий off? |
| CI/зависимости | Нет ли новых install scripts, mutable refs, лишних прав, секретов в PR-job или обхода security dependency? |

Для находки фиксируйте файл/строку и проверенный commit, предпосылки, путь
недоверенных данных, нарушенную границу, наблюдаемое последствие и регрессионный
тест. Разделяйте **подтверждено**, **нужна проверка** и **опровергнуто**. Для
неподтверждённой гипотезы укажите отсутствующий факт и безопасный способ проверки.
Отсутствие best practice само по себе не доказывает уязвимость.

Сканерные исключения допускаются только для конкретной доказанной тестовой
фикстуры/ложного срабатывания с причиной; не исключайте каталоги тестов или весь
тип секрета. Для отложенного исправления укажите владельца, область влияния,
причину и дату повторной проверки. Не используйте `npm audit fix --force`.
