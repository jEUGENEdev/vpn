# Android: приложения вне VPN

Исходная версия: `main` / `1f852aaf6f3b2e872b6e421fe47a05ac07949dc3`.
В `VpnService.Builder` отсутствовал список разрешённых приложений. Android
передавал в локальный VPN трафик всех UID, даже когда Go затем выбирал direct.
Поэтому запрет удалённого VPN-транспорта не исключал системный признак VPN
и виртуальный DNS для приложения без разрешения.

## Изменение границы защиты

В выборочном режиме `addAllowedApplication` включает только локально
идентифицированные приложения с решением `trusted`/`addresses` и саму «Сеть».
Пустой список не становится неограниченным VPN. Остальные приложения
используют обычную сеть и DNS; адресные правила внутри TUN на них не действуют.
Полный режим остаётся явным разрешением всему устройству. Сервер менять не нужно.

Каталог PackageManager позволяет выбирать исключённое приложение заранее.
Подпись и уникальный UID перепроверяются при создании интерфейса. Удалённые
приложения скрыты из списка, но их явные решения остаются для синхронизации:
переустановка не теряет локальный запрет, ещё не дошедший до сервера.

Перед сохранением расширения правил нативный слой захватывает объединение
старого и нового наборов. После сохранения применяется точный набор; ошибка
записи возвращает предыдущий охват. Неудачное `establish` не освобождает старый
дескриптор, а ошибка дублирования/старта стека после `establish` не освобождает
новый. Замена интерфейса закрывает потоки и изменяет `routeEpoch`.

## Проверки

- До изменения тесты `TestNativeScopeGrantMustCaptureBeforeConsent` и
  `TestNativeScopeExcludesUnapprovedAppsAndUpdates` воспроизводили ошибку:
  нативный охват не обновлялся (`calls=0`), разрешение сохранялось без захвата.
- `bash scripts/check.sh go`: форматирование, проверка модулей, полный прогон
  с `-race -tags with_gvisor`, `go vet` — PASS.
- Новые Go-тесты: ошибка нативного захвата до выдачи разрешения, ошибка записи
  при отзыве, пустой список, полный/выборочный режимы, восстановление правил
  аккаунта, смена идентичности APK, сохранение запрета после переустановки,
  удержание прежнего TUN при ошибке замены — PASS.
- `node scripts/test-ui-dom.cjs`: интерфейс и предупреждение о lockdown — PASS.
  Отдельно воспроизведена и исправлена ложная подпись о защите исключённого
  приложения во время общего сбоя VPN.
- `gomobile bind` для Android arm64/amd64; Gradle `assembleDebug` и
  `assembleDebugAndroidTest` — PASS. Сборки предназначены для проверки кода,
  не опубликованы как обновление и не меняют постоянную подпись установщика.
- `scripts/test-network-packaging.py`, синтаксис JS/shell, `git diff --check`
  и Gitleaks с редактированием секретов — PASS.

Нативный smoke-сценарий расширен receiver в **отдельном UID тестового APK**:
проверяются обычная активная сеть/DNS/HTTP до разрешения, захват и отсутствие
direct при доверии без сервера, исключение после отзыва, полный режим и возврат.
Receiver отсутствует в основном APK. Исправлен путь проверки сохранённых
профиля/правил при повторной установке: `files/core/`.

**Нативный сценарий здесь не запускался:** Android-устройства, эмулятора и KVM
нет. Сборка теста не подтверждает его прохождение. Госуслуги, Android lockdown,
смена сети, OEM-энергосбережение и захват IPv4/IPv6 требуют проверки на устройстве.
Полное сокрытие факта VPN не обещается: приложение может перечислять интерфейсы
независимо от активного маршрута. При глобальном lockdown Android лишает
исключённые приложения интернета; клиент показывает это и не снимает настройку.

Документация Android: [per-app VPN и lockdown](https://developer.android.com/develop/connectivity/vpn),
[перечисление интерфейсов](https://developer.android.com/reference/java/net/NetworkInterface).

## Дополнительная проверка перед слиянием

Обновлённая база OSV выявила существующую в `main` зависимость
`github.com/gorilla/websocket v1.5.3` с
[GO-2026-6278](https://pkg.go.dev/vuln/GO-2026-6278): предсказуемая маска
клиентских WebSocket-кадров. Зависимость Xray закреплена на исправленном
upstream-коммите `v1.5.4-0.20240701034025-d67f41855da4`, контрольные суммы
пересчитаны через Go modules. Другие версии не изменены, исключения сканера
не добавлены. Проверка воспроизводила находку до обновления и не находит её
после него.

На итоговой версии зависимости повторно пройдены полный `check.sh go`
(race, `with_gvisor`, vet, проверка модулей), `check-security.sh`, Android
`gomobile bind` arm64/amd64 и обе Gradle-сборки. Дополнительно пройдены
`check.sh desktop`, DOM-проверки и переносимые fixtures установщиков.

Полный `portable` не пройден: один Ansible fixture остановился с
`Local RPC server did not start`, отдельный SSH fixture — с
`Connection reset by peer`. Apple PlistBuddy пропущен на Linux.
Браузерный UI не запущен: комплектный Chromium отсутствует, системный Chromium
останавливается при `socket()` с `Operation not permitted`.
Дополнительный upstream-прогон WebSocket имеет ошибки в `TestProxyDial` и
`TestProxyAuthorizationDial` (`unexpected EOF`); те же ошибки воспроизведены
на исходной `v1.5.3` в той же среде. Этот прогон не считается PASS.
Утверждения и настройки проверок не ослаблялись.

GitHub Actions run `45277486002` завершился до исполнения команд security job
(0 steps), остальные jobs пропущены. Удалённый CI не считается пройденным;
локальная сборка не заменяет нативный smoke-тест.
