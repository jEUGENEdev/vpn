## Поведение и граница доверия

Раньше общее разрешение адреса давало VPN любому приложению, включая неизвестный
источник и приложение без согласия пользователя. Теперь выборочный режим требует
разрешения приложения: `addresses` или `trusted`. `pending`, `denied` и неизвестный
владелец сокета не получают VPN через общее правило. Защищённый адрес блокируется,
без автоматического прямого обхода. Отказ в разрешении не изображается как сбой VPN.

Полный режим — явное разрешение всем приложениям устройства. Он сохраняется
локально, использует существующий отдельный application credential и не создаёт
глобального правила адресов. При смене режима закрываются старые потоки;
`routeEpoch` отклоняет подключения, открывавшиеся по прежней политике. Ошибка записи
профиля оставляет прежний режим. Выключенный VPN не включается от смены режима.

В полном режиме TCP/UDP IPv4/IPv6 и DNS используют туннель. DNS поддерживает
все типы записей, включая HTTPS/ECH; максимум 64 одновременных запроса и таймаут
5 секунд. Нет повторной попытки через системный/прямой DNS. Проверяются соответствие
ответа запросу и актуальность политики; большой UDP-ответ запрашивает повтор по TCP.
Запрет серверного egress к private/loopback/metadata/reserved адресам сохранён.

Транспорт уже передаёт исходную HTTPS-сессию приложения без расшифровки. Новый
интеграционный сценарий через настоящий VLESS/XHTTP/REALITY проверяет сертификат
конечного сайта, исходные заголовки и отсутствие добавленных маркеров прокси.

## Воспроизведение до исправления

На исходном коде упали три новых теста: матрица отсутствия согласия, смена режима
через Action и реальное подключение неразрешённого приложения к разрешённому
туннельному адресу. Последний тест наблюдал успешное соединение вместо запрета.
После исправления эти же сценарии проходят. Проверки существующих сбоев транспорта
получили разрешение тестовому приложению, чтобы по-прежнему доходить до сетевого
сбоя, а не завершаться раньше на проверке согласия.

## Ограничения и следующий этап проверки

- Нужны нативные сценарии [acceptance.md](acceptance.md) на Windows, macOS и Android
  с наблюдением пакетов при отказе туннеля, смене режимов и ручном выключении.
- Полной невидимости для сайта нет: виден выходной IP/ASN сервера, сохраняются
  идентификаторы приложения и аккаунта. Проверка прозрачности HTTPS не доказывает
  нераспознаваемость VPN по IP или сетевому поведению.
- Desktop preview использует общий административный UI-token машины. Код с
  доступом к нему может изменить политику. Исправленная проверка владельца сокета
  не является sandbox против такого кода или root/Administrator; для этого нужна
  отдельная изоляция локального управления.
- После возврата к выборочному режиму собственный DNS/DoH-кэш приложения может
  скрывать домен. TTL 0 обычного DNS уменьшает кэширование, но не заменяет доверие
  всему приложению, если весь его трафик должен оставаться защищённым.
- Сервер должен быть обновлён для синхронизации `denied`; со старым сервером
  локальный запрет сохраняется, а ошибка синхронизации показывается пользователю.
  Полный режим использует уже существующий API `/api/app-vpn`.
- Неподдерживаемые протоколы и запрещённые локальные адреса блокируются. Служебные
  соединения к VPN/API и системные loopback-исключения не идут внутрь туннеля.
