# Доступность сети, отключение и удаление

Обычный сбой VPN больше не запускает recovery: разрешённые адреса и доверенные приложения остаются защищены блокировкой. Для прямого доступа используйте «Выключить VPN». Команды ниже — **явный административный обход защиты** при недоступной службе или удалённом клиенте; их нельзя вызывать автоматически после crash. Требуется новая сборка клиентов: `installers/current` не обновляется от изменения исходников.

[Текущая политика и проверки](fail-closed-vpn.md).

| Сценарий | Windows | macOS | Android |
|---|---|---|---|
| Выключить VPN | Закрыть Wintun, обычная сеть | Закрыть utun, обычная сеть | Закрыть VPN-дескриптор |
| Сбой процесса | Нет постоянного WFP-запрета | Нет постоянного PF-запрета/перезаписи DNS; supervisor запускает recovery | ОС закрывает VPN; lockdown должен быть выключен |
| Удаление | MSI: StopServices → recovery → удаление файлов | Деинсталлятор: остановка → recovery → удаление helper/UI | ОС удаляет VpnService и его интерфейс |
| Старые остатки | Отдельный PowerShell recovery без EXE | Миграция старых DNS/PF при запуске и recovery | Проверить системную блокировку без VPN |

## Если старый Windows-клиент уже удалён

Скачайте [recover-network.ps1](../packaging/windows/recover-network.ps1), при необходимости с другого устройства. Откройте PowerShell **от имени администратора**, перейдите в папку скрипта и выполните:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\recover-network.ps1
```

Обход execution policy действует только для этого запуска. Скрипт работает офлайн, отключает службу LineVPN, если она ещё существует, удаляет фиксированные фильтры старой версии и очищает DNS-кэш. Он не сбрасывает Windows Firewall или TCP/IP и не меняет DNS всех адаптеров. Повторный запуск безопасен при уже отсутствующих объектах. Ошибка WFP выводится, а не скрывается сообщением об успехе.

Для установленной новой версии можно использовать агент:

```powershell
Set-Service LineVPN -StartupType Disabled
Stop-Service LineVPN
& 'C:\Program Files\LineVPN\resources\agent\linevpn-agent.exe' -recover-network
```

## macOS

Новая версия восстанавливает DNS старой версии, не меняя пользовательские настройки, которые уже отличаются от DNS Линии. При отсутствующем/повреждённом бэкапе удаляется только `172.29.255.2`, при отсутствии других DNS возвращается DHCP. Ошибка одного интерфейса не мешает обработке остальных. Ошибки очистки не скрываются.

Для работающего VPN используется временная DNS-запись SystemConfiguration, привязанная к сессии `scutil`. Агент держит её stdin открытым; завершение агента, включая SIGKILL, закрывает канал и завершает сессию. DNS физических адаптеров не переписывается. Семантика удаления временной записи описана в [документации Apple](https://developer.apple.com/documentation/systemconfiguration/scdynamicstoreaddtemporaryvalue(_:_:_:)). Нативный тест проверяет системный DNS после включения и отсутствие временной записи после остановки.

```bash
sudo '/Library/Application Support/LineVPN/recover-network.sh'
```

Полное удаление: **«Удалить Линию VPN»** в трее или `Uninstall-LineVPN.command` из нового DMG. Файлы удаляются только после успешного восстановления сети. Профиль остаётся в `/var/lib/linevpn`.

Если `/Applications/LineVPN.app` ранее был обнаружен и затем отсутствует 30 секунд, supervisor отключает службу и освобождает сеть. Это не заменяет полное удаление служебных файлов. Для установки приложения в другое место используйте явный деинсталлятор.

## Android

Отключите **«Блокировать соединения без VPN»** в системных настройках VPN. Приложение не может изменить эту настройку или корпоративную политику администратора. При включённой блокировке закрытие VPN может лишить устройство интернета даже при исправном клиенте; интерфейс сообщает об этом и открывает настройки.

Выключение, остановка службы и отзыв VPN-разрешения закрывают дескриптор и отменяют отложенный запуск. Ошибка создания туннеля оставляет UI для выключения/повтора. При удалении APK настройки VPN освобождает Android.

## Проверка

Проверьте DNS и прямой HTTP после off, stop, принудительного завершения, обновления и удаления. Перезапустите браузер, если он сохранил Fake-IP старого клиента. Не сбрасывайте глобальные настройки сети без отдельной диагностики.

Unit/DOM-тесты и кросс-сборки не подтверждают поведение ОС. Реальные сценарии перечислены в [acceptance.md](acceptance.md) и автоматизированы в нативных тестовых скриптах. [Результаты и ограничения текущей проверки](network-availability-verification.md).
