# Отключение и удаление

В версии 0.4 отдельные пользовательские инструменты восстановления убраны.
Для обычного прямого доступа используйте **«Выключить VPN»**. Если клиент сломан,
выполните **полное удаление, затем новую установку** по [инструкции](installer-upgrade.md).

| Сценарий | Windows / macOS | Android |
| --- | --- | --- |
| Выключение VPN | Закрываются TUN и принадлежащие клиенту сетевые ограничения | Закрывается VPN или используется прямой режим при lockdown |
| Сбой процесса | Постоянные WFP/PF сохраняют защиту; прямого резерва нет | Защита при смерти процесса требует системного lockdown |
| Явное удаление | Остановка процессов → очистка собственных сетевых объектов → удаление файлов и локальных данных | ОС удаляет пакет и VPN-службу |
| Новая установка | Новая служба и сессия, проверка API/TUN/фильтра | Новый вход и системное разрешение VPN |

Сетевой сбой сам по себе не разрешает прямой доступ. Внутренняя функция очистки
остаётся частью выключения и удаления: без неё после удаления клиента могли бы
остаться блокировки интернета. Она не сбрасывает чужие правила PF/WFP или настройки
всех адаптеров. На macOS временная DNS-запись заканчивается вместе с `scutil`;
старые DNS приложения удаляются только в рамках явного удаления.

Профиль и ключ доступа сохраните до удаления. После него закройте и заново
откройте приложения, которые могли сохранить старые Fake-IP в своём DNS-кэше.
На Android настройки «Постоянная VPN» и «Блокировать соединения без VPN» задаёт
пользователь или администратор устройства; приложение не меняет их самостоятельно.

Проверяйте DNS и прямой HTTP после явного off и удаления. После crash при
включённом VPN защищённый трафик должен оставаться заблокированным.
[Границы защиты](security.md), [сценарии проверки](acceptance.md).
