# Развёртывание сервера

Требуется чистый VPS Debian 12/13 или Ubuntu 24.04/26.04, Linux amd64, публичный IPv4/IPv6 и SSH. Домен и покупной сертификат не нужны. Порты: TCP 443 для REALITY, TCP 8443 для TLS API и админки, ваш SSH-порт. На хосте не должны работать другие сервисы на 443/8443.

## GitHub Actions

В **Settings → Secrets and variables → Actions → Repository secrets** добавьте:

| Секрет | Значение |
|---|---|
| `VPS_HOST` | Публичный IP сервера, без `ssh`, имени пользователя и порта |
| `VPS_USERNAME` | SSH-пользователь, например `root` |
| `VPS_PASSWORD` | Пароль SSH-пользователя |

Необязательные секреты: `VPS_PORT` (по умолчанию 22), `VPN_ADMIN_PASSWORD` (16–72 байта, без пробелов по краям), `VPS_KNOWN_HOSTS` (проверенная запись OpenSSH known_hosts). Если пользователь не root, нужен доступ sudo с тем же паролем либо без пароля.

Откройте **Actions → Deploy VPN server → Run workflow**, выберите `main`. Workflow также запускается при изменениях серверного кода или файлов деплоя в `main`. В pull request выполняется только проверка конфигурации; доступа к VPS нет. Изменение секрета само по себе не запускает workflow: после добавления секретов нажмите **Re-run all jobs** у остановившегося запуска или **Run workflow**.

Сначала проверяются секреты; при отсутствии обязательных значений запуск завершается с их названиями до сборки и подключения. Затем GitHub runner запускает тесты серверной части, собирает Linux-бинарники, применяет Ansible и проверяет `/healthz` через HTTPS с полученным по SSH сертификатом, а также доступность TCP 443. Компилятор на VPS не устанавливается. Одновременные деплои в `main` выполняются по очереди.

Пароли читаются из окружения runner, не передаются в аргументах shell и не записываются в репозиторий. При отсутствии `VPN_ADMIN_PASSWORD` Ansible создаёт случайный пароль админки один раз в `/etc/linevpn/admin-password` с правами 0600 и сохраняет его при обновлениях. Узнать его можно по SSH: `sudo cat /etc/linevpn/admin-password`. Если секрет `VPN_ADMIN_PASSWORD` задан, он становится паролем админки при каждом деплое.

Без `VPS_KNOWN_HOSTS` используется первое доверие SSH (`accept-new`) внутри запуска. Для проверки заранее известного ключа добавьте проверенную запись в этот секрет; тогда включается `StrictHostKeyChecking=yes`. Один `ssh-keyscan` без независимой проверки не подтверждает подлинность ключа.

После успешного деплоя профиль подключения доступен в админке: **«Профиль сервера» → «Скопировать профиль»** или **«Скачать .txt»**. Артефакт **vpn-client-bootstrap** остаётся резервным способом получить профиль и публичный сертификат API. Паролей и закрытых ключей в профиле и артефакте нет. Проверки workflow подтверждают установку и доступность сервера; полный туннель на устройствах проверяется по [приёмке](acceptance.md).

## Ручной запуск одним файлом

Из корня клона или распакованного архива **всего репозитория**:

| Система на вашем компьютере | Запуск |
|---|---|
| Linux / macOS | `bash deploy.sh` |
| Windows | Двойной щелчок по `deploy.bat` или запуск из CMD |

Оба файла используют `scripts/deploy-manual.py` и существующий Ansible playbook. Не переносите только `.sh`/`.bat` отдельно от остальных файлов. GitHub Actions, его секреты и доступ к GitHub с самого VPS не нужны. Скрипт устанавливает текущую локальную версию исходников; перед обновлением выполните `git pull --ff-only` самостоятельно.

### Подготовка компьютера

Требуются **Python 3.12+**, **Go 1.27.4+**, Bash и OpenSSH. Ansible и его коллекции скрипт установит сам. Go устанавливается на управляющем компьютере, а не на VPS. На VPS должен быть Python 3 и доступ root либо sudo. Для сборки нужны доступ к Go-модулям, PyPI и Ansible Galaxy.

Для Ubuntu 24.04 (в том числе внутри WSL):

```bash
sudo apt-get update
sudo apt-get install -y python3 python3-venv openssh-client ca-certificates
# Установите Go по https://go.dev/doc/install и добавьте его bin в PATH.
go version
python3 --version
```

На Windows предварительно установите WSL с Ubuntu, откройте Ubuntu и создайте Linux-пользователя:

```bat
wsl --install -d Ubuntu-24.04
```

Python, Go и перечисленные пакеты должны быть установлены **внутри WSL**. BAT использует дистрибутив WSL по умолчанию и login shell, чтобы загрузить PATH из Linux-профиля. Можно выбрать другой установленный дистрибутив в CMD:

```bat
set "LINEVPN_WSL_DISTRO=Ubuntu-24.04"
deploy.bat
```

Путь репозитория передаётся через [WSLENV с преобразованием пути](https://devblogs.microsoft.com/commandline/share-environment-vars-between-wsl-and-windows/), поэтому пробелы и кириллица не требуют ручной правки BAT. Управление WSL описано в [документации Microsoft](https://learn.microsoft.com/en-us/windows/wsl/basic-commands). Для запуска BAT из другого скрипта без завершающей паузы задайте `LINEVPN_NO_PAUSE=1`; код ошибки сохраняется.

### Что спросит скрипт

1. Публичный IPv4/IPv6 сервера, SSH-пользователя (по умолчанию `root`) и порт (по умолчанию `22`).
2. OpenSSH при необходимости запросит пароль SSH либо пароль ключа. При первом подключении сравните отпечаток ключа с данными консоли VPS. Изменившийся ключ не принимается автоматически.
3. Пароль админки: 16–72 UTF-8 байта и повтор для проверки. **Пустой ввод создаёт случайный пароль при первой установке и сохраняет существующий при обновлении**.
4. Для пользователя не `root` — пароль sudo; при sudo без пароля оставьте поле пустым.

Пароль SSH обрабатывает OpenSSH. Ansible использует временное multiplex-соединение, которое закрывается после завершения или ошибки. Пароли админки и sudo передаются только окружением Ansible, не записываются в inventory, командную строку или репозиторий. Ввод паролей скрыт. Секреты GitHub локальный запуск не читает; если хотите тот же пароль админки, введите его вручную. Последующий Actions-деплой с заданным `VPN_ADMIN_PASSWORD` снова применит этот секрет.

Скрипт проверяет окружение, создаёт Ansible-окружение в `~/.cache/linevpn` (или `$XDG_CACHE_HOME/linevpn`), запускает тесты серверных пакетов, собирает Linux amd64-бинарники и применяет playbook. Playbook включает UFW с разрешением SSH/443/8443, создаёт или обновляет службу и при изменениях перезапускает её. Используйте отдельный VPS; при обновлении возможен краткий разрыв VPN-сессий.

В финале выполняются проверка `/healthz` с сертификатом, полученным по SSH, и подключение к TCP 443. Только после их успеха выводятся адрес админки, публичный профиль и команда получения пароля. При ошибке процесс возвращает ненулевой код, а сообщение об успехе не выводится. Автоматического отката выполненных серверных изменений нет: исправьте причину и повторите запуск.

### Параметры и результат

```bash
# Интерактивный запуск:
bash deploy.sh

# С заранее известными параметрами и SSH-ключом:
bash deploy.sh --host YOUR_PUBLIC_IP --user root --port 22 --key ~/.ssh/id_ed25519

# Готовые серверные бинарники уже находятся в build/; Go и тесты не запускаются:
bash deploy.sh --use-build

bash deploy.sh --help
```

При `--use-build` положите **оба** доверенных файла `linevpn-server-linux-amd64` и `linevpn-keygen-linux-amd64` в `build/`. Проверка формата ELF подтверждает платформу, но не происхождение бинарников. Этот параметр доступен через SH, в том числе из терминала WSL.

Результат: `https://IP:8443/` и файлы `deploy/ansible/generated/vpn1-bootstrap.txt` / `vpn1-api-cert.pem`. Настройте доверие браузера к полученному сертификату, войдите в админку, скопируйте **«Профиль сервера»**, зарегистрируйтесь в клиенте и одобрите заявку. Проверка слушателей не заменяет проверку туннеля на устройстве. При последовательном деплое на разные VPS файлы `vpn1-*` перезаписываются результатом последнего запуска; сохраняйте нужные публичные профили отдельно.

Если на VPS нет Python: установите `python3` по SSH и повторите запуск. Если сессия SSH прервётся, повторите скрипт: сохранённого пароля для автоматического переподключения нет. Для диагностики службы используйте `sudo journalctl -u linevpn -n 100 --no-pager`.

## Пошаговая установка через Ansible

На управляющей машине установите Go 1.27.4 и Python 3.12+, клонируйте репозиторий и выполните:

```bash
scripts/build-server.sh
python3 -m pip install -r deploy/requirements.txt
cd deploy/ansible
cp inventory.example.ini inventory.ini
cp group_vars/vpn.example.yml group_vars/vpn.yml
ansible-galaxy collection install -r requirements.yml
ansible-vault create group_vars/vault.yml
```

В `inventory.ini` укажите VPS и `ansible_port`, если SSH работает не на 22. Firewall использует этот порт, если `vpn_ssh_port` не переопределён. В зашифрованном `group_vars/vault.yml` сохраните:

```yaml
vault_admin_password: "ВАШ_УНИКАЛЬНЫЙ_ПАРОЛЬ_16_72_БАЙТА"
```

Передайте vault-файл явно, потому что он не является группой inventory:

```bash
ansible-playbook deploy.yml --extra-vars @group_vars/vault.yml --ask-vault-pass
```

Playbook создаёт пользователя `linevpn`, ключи REALITY, сертификат TLS с IP в SAN, systemd-службу, месячное обновление сертификата и firewall. Ключи создаются только один раз. Повторный запуск не меняет закреплённый публичный ключ API. Секреты и сгенерированные профили исключены из Git.

После установки в `deploy/ansible/generated/` появятся профиль `linevpn://IP:8443?pin=…` и сертификат API. Они получены по проверенному SSH-соединению. Профиль содержит публичный отпечаток, а не пароль аккаунта.

## Админка

Адрес: `https://IP:8443/`. Пароль задаётся через `vault_admin_password` / секрет `VPN_ADMIN_PASSWORD` либо создаётся автоматически; на VPS он находится в `/etc/linevpn/admin-password` с режимом 0600. Внесите полученный по SSH сертификат в доверенные сертификаты своего браузера/ОС. Не подтверждайте неизвестный сертификат без проверки. Клиент проверяет SPKI-отпечаток автоматически и отклоняет подмену, просроченный сертификат и HTTP-переадресацию.

Регистрация создаёт `pending`. До одобрения не выдаются рабочие данные устройства. Администратор может одобрить/отклонить заявку, заблокировать аккаунт и отозвать отдельное устройство. Блокировка/отзыв перестраивает Xray и завершает существующие сессии.

### Профиль сервера

После входа откройте раздел **«Профиль сервера»** в меню. Админка получает текущую ссылку подключения; её можно скопировать или скачать файлом `linevpn-server.txt`. Кнопка **«Обновить профиль»** повторно формирует ссылку из адреса API в конфигурации и отпечатка действующего сертификата. Она не меняет ключи или сертификат и не прерывает VPN-сессии.

`GET /api/admin/bootstrap` требует действующей сессии администратора и возвращает только поле `profile`. Для адреса используются настройки сервера, а не HTTP Host; поддерживаются IPv4 и IPv6. При недоступном, просроченном или не соответствующем адресу сертификате профиль не выдаётся. Профиль не предоставляет доступ к аккаунтам: регистрация и одобрение остаются обязательными.

## Обслуживание

```bash
sudo systemctl status linevpn
sudo journalctl -u linevpn -n 50
sudo systemctl status linevpn-renew.timer
```

Резервируйте `/etc/linevpn` и `/var/lib/linevpn` в зашифрованном виде. Для согласованной копии BoltDB остановите службу или используйте snapshot-транзакцию. Потеря ключа API требует нового профиля на устройствах. При смене IP требуется обновить конфигурацию и сертификат; playbook не заменяет их молча.

Сборки сервера также сохраняются как артефакт workflow `server-binaries`. Проверка `-check` проверяет поля конфигурации; полный запуск проверяет совместимость Xray и доступность слушателей.
